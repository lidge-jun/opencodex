OpenCodex 會限制保留的回應診斷資料量，但記錄上限不會限制傳給用戶端的位元組數。供應商、請求及傳輸層的其他限制仍各自適用。

## JSON 與一般錯誤回應

JSON 檢查最多保留 32 MiB 的來源位元組。若回應主體超過此額度，記錄功能會捨棄保留的副本，並繼續轉送原始回應。它不會把截斷的前段解析成具權威性的用量或模型中繼資料。其他可信路徑已提供的用量會保留；缺少用量時不會憑空補上零值。一般非 JSON 錯誤診斷僅保留前 8 KiB，並經過現有的遮蔽邏輯。

用戶端讀取時就會收到資料區塊，無須等待整份主體完成診斷檢查。讀取失敗會在請求歷史中記為 502，取消則記為 499；這些診斷結果不會改寫已送出的 HTTP 標頭。記錄只會完成一次。

## 串流回應

當原生 SSE 檢查進度遠超過用戶端消耗進度時，檢查會暫停。額度為 32 MiB，加上來源區塊與原生預取的額外開銷；它不是回應總大小上限，也不是整個程序的記憶體上限。更長的回應仍會檢查到實際完成事件，包括最終用量與接續狀態。

用戶端中斷連線後，現有的有界排空程序仍可在最多 15 秒或額外 32 MiB 的檢查範圍內觀察較晚到達的完成事件。強制關閉則不同：它會捨棄尚未完成的候選項，不會把它們記成已完成回應。現有的傳輸選擇與 WebSocket 記憶體界限不變。不需要新增設定。
