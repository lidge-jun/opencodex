---
title: Настольное приложение
description: Установка и использование настольного приложения OpenCodex на macOS, Windows и Linux.
---

Настольное приложение OpenCodex объединяет нативный значок в системной панели и веб-дашборд. Его
встроенный CLI находит существующий локальный прокси; приложение запускает встроенную среду
выполнения только после подтверждения, что прокси отсутствует.

Дашборд отдаётся с найденного локального эндпоинта прокси (по умолчанию порт `10100`).
Настольное приложение служит локальной оболочкой для дашборда и встроенной среды выполнения.

## Установка

### macOS

Загрузите `OpenCodex-<version>-macos.dmg` из
[последнего выпуска](https://github.com/lidge-jun/opencodex/releases). Откройте DMG и перетащите
`OpenCodex.app` в Applications. Для приложения требуется macOS 13 или новее.

Релизные сборки `OpenCodex.app` подписаны Developer ID и нотариально заверены Apple, поэтому при
первом запуске macOS обычно запрашивает лишь стандартное подтверждение для загруженного приложения.
Если macOS всё же блокирует его, используйте **System Settings → Privacy & Security → Open Anyway**.

### Windows

Загрузите `OpenCodex-<version>-windows-x64.msi` и запустите установщик. Windows SmartScreen может
показать предупреждение, поскольку установщик пока не подписан кодовой подписью; после проверки,
что файл загружен со страницы выпуска, выберите **More info → Run anyway**.

### Linux

Загрузите `OpenCodex-<version>-linux-x86_64.AppImage` или
`OpenCodex-<version>-linux-amd64.deb` со страницы выпуска.

Для AppImage:

```bash
chmod +x OpenCodex-<version>-linux-x86_64.AppImage
./OpenCodex-<version>-linux-x86_64.AppImage
```

Для дистрибутивов на основе Debian:

```bash
sudo apt install ./OpenCodex-<version>-linux-amd64.deb
```

Для значка в системной панели нужна среда рабочего стола с поддержкой AppIndicator.

## Первый запуск

Приложение просит встроенный CLI выполнить `ocx resolve --json` и подключается к доступному
локальному прокси, если тот уже работает. Оно запускает встроенную среду выполнения, только если
CLI подтвердил отсутствие прокси; неопределённый результат показывается как ошибка запуска.
Затем дашборд открывается в webview приложения по найденному loopback-адресу.
Если приложение запущено при входе в систему и скрыто в системной панели, оно оставляет лёгкую
страницу запуска и загружает дашборд при первом открытии из панели или при повторном запуске.

Используйте действия **Open dashboard** или **Open in browser** в системной панели, чтобы
переключаться между встроенным дашбордом и обычным браузером. Там же доступны проверки обновлений.

## Использование в системной панели

На macOS и Windows нажмите значок в системной панели, чтобы открыть компактное окно использования.
Действие **Show usage** тоже открывает его, в том числе в средах Linux, где значок не передаёт
события нажатия. В Linux дашборд открывается при запуске, даже если среда рабочего стола
не показывает значок в панели.

Окно использования показывает итоги за сегодня и за 30 дней, настроенный график, компактный
список моделей и лимиты провайдеров и аккаунтов. Рядом с полосами квот указан обратный отсчёт
до сброса; наведите курсор, чтобы увидеть точное время. Видимые разделы и график определяются
существующими настройками **Menu bar & widget**. Скрытые провайдеры не учитываются в заголовке,
итогах, квотах и графике. График включает активность текущего интервала. Индикатор частичных
данных означает, что часть данных графика нельзя надёжно отнести к источнику. Отсутствующие
измерения не отображаются как нулевое использование. На Windows и Linux прокрутите длинный список
аккаунтов в окне, чтобы добраться до Refresh и Dashboard.

На macOS окно использует нативные элементы SwiftUI и прокручиваемую панель AppKit. На macOS 26
и новее применяется Apple Liquid Glass, на более старых системах — нативный материал всплывающей
панели. Заголовок и кнопки Refresh и Dashboard остаются видимыми при прокрутке длинных списков
аккаунтов. Окно также открывается через **View → Show Usage** (Command-Shift-U).
Нажмите Escape или вне панели, чтобы закрыть её.

Меню системной панели показывает число запросов и токенов за сегодня, а при включённой настройке —
оценочную стоимость. Оно использует те же данные за локальные сутки, что и виджет. Выберите
**Refresh now** для немедленного обновления; приложение также обновляет данные каждые 60 секунд.
Настройки отображения остаются в разделе **Menu bar & widget** дашборда. Отключение **Today**
скрывает сводку, а отключение **Cost** убирает из неё стоимость.

Недоступное использование или использование без явного измерения показывается как `—`, а не как
измеренный ноль. Выбор заголовка только со значком очищает прежний счётчик. Сокращения сохраняют
нули целых чисел: десять миллионов токенов — это `10M`, а не `1M`.

## Обновления

Выберите **Check for Updates…** в меню системной панели для немедленной проверки. Релизные
сборки также проверяют обновления после запуска и каждые шесть часов. Перед установкой обновления
проверяются подписанным открытым ключом обновлений проекта. На macOS обновления внутри приложения
загружают `OpenCodex-<version>-macos.app.tar.gz`; DMG предназначен для первой установки.
Манифест выпуска создаётся только при наличии секрета ключа обновлений и в таком случае
требует подписи всех четырёх платформ.

## Виджет

Приложение macOS включает расширение OpenCodex WidgetKit. Настройка виджета и сведения о локальном
снимке описаны в [руководстве по приложению в строке меню macOS](/ru/guides/macos-menu-bar/).

## Удаление

На macOS перетащите `OpenCodex.app` из Applications в корзину. На Windows удалите OpenCodex через
**Installed apps**. В Linux на базе Debian выполните:

```bash
sudo apt remove opencodex
```

Для AppImage удалите загруженный файл.

Если сохранённые настройки строки меню не читаются, частичные изменения отклоняются ради
сохранности файла. Восстановите файл или явно сбросьте настройки сопутствующего приложения,
прежде чем редактировать их снова.
