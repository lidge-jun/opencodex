Вкладка **Models → Routing** в дашборде OpenCodex позволяет управлять `config.routingProfiles` без ручного редактирования `config.json`.

## Создание профиля

1. Откройте **Routing** в дашборде.
2. Выберите **Create profile**.
3. Укажите `id`. Канонический id модели имеет вид `policy/<id>`.
4. Добавьте одного или нескольких явных кандидатов provider/model.
5. Настройте необязательные требования, веса оценки, ограничения стоимости (`maxEstimatedCostUsd`, необязательный `onUnknownCost`) и поведение при неизвестных данных.
6. Сохраните профиль.

После создания id профиля изменить нельзя. Если нужен другой id, создайте новый профиль, обновите вызывающие стороны и удалите старый.

## Проверка и сохранение

Дашборд отправляет в API управления тот же объект профиля, который используется в `config.routingProfiles`. Перед записью сервер проверяет кандидата целиком:

- id и алиасы должны соблюдать правила именования и исключения конфликтов профилей маршрутизации;
- каждый провайдер-кандидат должен существовать и быть включённым;
- повторяющиеся кандидаты отклоняются;
- числовые лимиты и требования должны оставаться в допустимых диапазонах;
- хотя бы один вес оптимизации должен быть положительным.

При успешном сохранении профиль записывается обычным механизмом конфигурации, согласуется с текущим состоянием и обновляет каталог моделей. При ошибке проверки прежняя конфигурация не меняется, а ошибка показывается в редакторе.

Если задан `limits.maxEstimatedCostUsd`, для `limits.onUnknownCost` по умолчанию используется `"allow"`: неизвестная оценка стоимости не исключается именно из-за лимита, а трассировки пробной и реальной маршрутизации помечают `cost.capOutcome: "unknown-allowed"`, чтобы оператор видел, что соблюдение лимита не доказано. Укажите `"exclude"`, если потолок должен закрываться отказом (`cost-limit-unknown` и `cost.capOutcome: "unknown-excluded"`). Один только `onUnknownCost` ничего не меняет и не создаёт отметку о результате лимита. Это отдельно от `unknownEvidence.cost`, который может независимо исключать или штрафовать неизвестные цены.

## Пробная оценка сохранённого профиля

Возможности кандидата определяются по итоговой конфигурации провайдера после применения переопределений реестра. Поэтому требования к расположению (`localOnly` и `remoteAllowed`) используют фактический адрес вышестоящего сервиса. Если адрес нельзя классифицировать, допуск определяет настройка `unknownEvidence.capability` профиля. Неверная конфигурация провайдера, которую нельзя разрешить, всегда исключается с `route-unavailable`, даже если неизвестные возможности разрешены. Отсутствующие или отключённые провайдеры также исключаются с `route-unavailable` до оценки.

Выберите сохранённый профиль и используйте **Dry-run evaluation**, чтобы добавить сведения о запросе: размер контекстного окна, использование инструментов, входное изображение или структурированный вывод. Пробный запуск оценивает допуск и баллы, но не отправляет запрос вышестоящей модели.

Несохранённые изменения не участвуют в пробном запуске. Сначала сохраните профиль, чтобы показанные версия и оценка относились к одной конфигурации.

## API управления

Редактор использует следующие эндпоинты:

- `GET /api/routing-profiles` перечисляет нормализованные профили и версии.
- `PUT /api/routing-profiles` создаёт или обновляет один профиль. Передайте `mode: "create"` или `mode: "update"`; режим создания не перезаписывает существующий id.
- `DELETE /api/routing-profiles?id=<id>` удаляет один профиль.
- `POST /api/routing-profiles/dry-run` оценивает сохранённый профиль без отправки запроса вышестоящему сервису.

Пример данных для сохранения:

```json
{
  "id": "fast",
  "mode": "create",
  "profile": {
    "alias": "ocx/fast",
    "candidates": [
      { "provider": "anthropic", "model": "claude-sonnet-5" },
      { "provider": "openai", "model": "gpt-5.6" }
    ],
    "require": { "tools": true, "minContextWindow": 128000 },
    "optimize": { "latency": 0.55, "health": 0.25, "cost": 0.1, "quota": 0.1 },
    "limits": { "maxEstimatedCostUsd": 0.5, "onUnknownCost": "allow" },
    "unknownEvidence": {
      "capability": "exclude",
      "health": "penalize",
      "quota": "penalize",
      "cost": "penalize"
    }
  }
}
```
