## Обзор

Video Bridge позволяет использовать генерацию xAI Grok Imagine Video через любую не-OpenAI модель,
маршрутизируемую opencodex. Когда мост включён, в разговор добавляется синтетический tool
`video_gen`. Модель вызывает его как обычный function tool; opencodex перехватывает вызов,
отправляет job на генерацию видео в xAI, опрашивает её до завершения и скачивает результат.

По умолчанию задания уходят в xAI; `images.videoProvider` может направить их в другой совместимый бэкенд.

## Предварительные требования

Эти предварительные условия относятся к назначению xAI по умолчанию. Если задан `images.videoProvider`, см. [Выбор видеопровайдера](#выбор-видеопровайдера).

- Нужна запись провайдера `xai` с **API-ключом** (`ocx login xai` сам по себе недостаточен —
  video bridge требует key auth, а не OAuth)
- Активной маршрутизируемой моделью должна быть не-OpenAI модель (например, Anthropic Claude или
  Google Gemini)
- opencodex должен быть настроен на маршрутизацию через этого не-OpenAI провайдера

> **⚠ Provider key required:** Video Bridge активируется только тогда, когда провайдер `xai`
> использует аутентификацию по API-ключу. Добавьте в конфигурацию:
>
> ```json
> {
>   "providers": {
>     "xai": { "adapter": "openai-chat", "apiKey": "${XAI_API_KEY}", "authMode": "key" }
>   }
> }
> ```
>
> Задайте `XAI_API_KEY` в окружении запуска прокси, сохраняя `${XAI_API_KEY}` и `authMode: "key"`. Экспорт в другом терминале не меняет работающий прокси; перезапустите через владеющее им Desktop, службу или терминал. Не публикуйте ключи в коммитах и журналах.

## Конфигурация

Добавьте `videoBridgeEnabled: true` в раздел `images`:

```json
{
  "images": {
    "bridgeEnabled": true,
    "videoBridgeEnabled": true,
    "videoBridgeModel": "grok-imagine-video-1.5-lite",
    "videoMaxRounds": 2,
    "videoTimeoutMs": 300000
  }
}
```

| Параметр | По умолчанию | Описание |
|--------|---------|-------------|
| `videoBridgeEnabled` | `false` | Главный переключатель. Должен быть явно включён. |
| `videoBridgeModel` | `"grok-imagine-video-1.5-lite"` | Id видеомодели xAI. |
| `videoMaxRounds` | `2` | Максимум раундов video-gen до принудительного финального ответа. |
| `videoTimeoutMs` | `300000` (5 min) | Таймаут одного видео, включая polling. |
| `videoProvider` | не задан (xAI) | Необязательный провайдер с API-ключом, который обслуживает `video_gen` через свой `baseUrl` и ключ. См. [Выбор видеопровайдера](#выбор-видеопровайдера). |

## Выбор видеопровайдера

По умолчанию мост отправляет задания `video_gen` в xAI с API-ключом провайдера `xai`. Задайте `images.videoProvider`, чтобы отправлять их в другой бэкенд с тем же асинхронным API (`POST {baseUrl}/videos/generations`, затем `GET {baseUrl}/videos/{id}`), например в собственный медиамост:

```json
{
  "providers": {
    "my-video-bridge": {
      "adapter": "openai-chat",
      "baseUrl": "http://127.0.0.1:8790/v1",
      "apiKey": "${VIDEO_BRIDGE_KEY}",
      "authMode": "key",
      "allowPrivateNetwork": true
    }
  },
  "images": {
    "videoBridgeEnabled": true,
    "videoProvider": "my-video-bridge",
    "videoBridgeModel": "grok-imagine-video-1.5-lite"
  }
}
```

- Назначением и учётными данными служат только `baseUrl` и API-ключ указанного провайдера. Адаптер не важен, но нужна аутентификация по API-ключу.
- `"videoProvider": "xai"` сохраняет закреплённый адрес `https://api.x.ai/v1` независимо от `baseUrl` в записи `xai`. Другие встроенные идентификаторы провайдеров отклоняются; укажите пользовательского провайдера.
- Для `baseUrl` в loopback или частной сети этому провайдеру нужен `allowPrivateNetwork: true`, как и для остального трафика провайдеров.
- Ключ, который OpenCodex может опознать как ключ xAI (ключ формата `xai-`, ключ любой записи `xai` или ссылка на переменную окружения с xAI или Grok в имени), отправляется только на `https://api.x.ai` или `https://cli-chat-proxy.grok.com`; любой другой источник отклоняется. Ключ без этих признаков опознать нельзя, поэтому не вставляйте ключ xAI в запись другого провайдера. Ссылка на секрет другого провайдера в связке ключей всегда отклоняется, приостановленный активный ключ тоже отклоняется, а `baseUrl` не может содержать учётные данные, query или fragment.
- Если провайдер отсутствует, отключён, приостановлен, не имеет ключа или отклонён, каждый вызов `video_gen` возвращает модели эту ошибку. Ничего не отправляется, и мост никогда не переключается на xAI.
- В протоколе xAI готовое видео скачивается только по base64 URL `data:` или публичному URL `https:`, поэтому локальный мост должен вернуть один из них в `video.url`. Бэкенд, который отдаёт файл со своего хоста, вместо этого задаёт `"videoApi": "openai"` (см. [раздел OpenAI Videos API в английском руководстве](/guides/video-bridge/#openai-videos-api-backends)).

## Как это работает

1. opencodex обнаруживает не-OpenAI маршрутизируемую модель с `videoBridgeEnabled: true`
2. В разговор внедряется синтетический function tool `video_gen`
3. Когда модель вызывает `video_gen`, opencodex отправляет job в `/videos/generations` xAI (или в настроенный `images.videoProvider`)
4. Bridge опрашивает статус job каждые 5-15 секунд и отправляет heartbeat-сообщения, чтобы поток не умер
5. Когда видео готово, оно скачивается в каталог artifacts
6. Локальный путь к файлу возвращается модели как результат tool

## Поддерживаемые параметры

Tool `video_gen` принимает:

| Параметр | Тип | Диапазон | Описание |
|-----------|------|-------|-------------|
| `prompt` | string | необязателен при наличии изображения или кадра | Текстовый запрос |
| `duration` | integer | 1-15 | Длительность видео в секундах |
| `resolution` | string | `480p`, `720p`, `1080p` | Зависит от модели; не выше 720p с `last_frame`, `keyframes` или `reference_images` |
| `aspect_ratio` | string | зависит от модели | `16:9`, `9:16`, `1:1`, `4:3`, `3:4`, `3:2`, `2:3`, `21:9`, `5:2`; отклоняется при анимации только `image`, которая сохраняет свои пропорции |
| `image` | string | первый кадр | HTTPS URL, URL данных или сохранённый артефакт |
| `last_frame` | string | только 1.5 | Последний кадр |
| `keyframes` | array | 1.5, максимум 4 | `{image, timestamp_s}`; временная метка строго внутри клипа (8 s, если `duration` не указан) |
| `reference_images` | array | 1.5: 14, классическая: 7 (≤ 10 s) | Опорные изображения; классическая модель не может сочетать их с `image` |

Настройки, которые модель не может выполнить, отклоняются до любого платного вызова, а не игнорируются.

### Модели и входные изображения

| Модель | Разрешение | Входные данные | за секунду (480p / 720p / 1080p) |
|-------|------------|--------|------------------|
| `grok-imagine-video-1.5` | 480p / 720p / 1080p нативное | первый/последний кадр, 4 ключевых кадра, 14 референсов (720p максимум) | $0.08 / $0.14 / $0.25 |
| `grok-imagine-video-1.5-lite` (по умолчанию) | 480p / 720p / 1080p увеличенное | первый кадр | $0.02 / $0.03 / $0.14 |
| `grok-imagine-video` | 480p / 720p | первый кадр, 7 референсов | $0.05 / $0.07 / — |

Для ключевых кадров или референсов задайте `images.videoBridgeModel` равным `grok-imagine-video-1.5`. Известные модели поддерживают девять пропорций; неизвестные сохраняют семь, 480p/720p и не принимают изображения. Допускаются HTTPS URL и данные PNG/JPEG/WebP размером до 10 МиБ после декодирования. Изображение, скачанное мостом, можно в течение часа указать через URL артефакта, абсолютный путь или URL `file:`: используется сохранённый исходный URL без чтения локального файла. Это работает только с фиксированным адресом xAI, не с пользовательским `images.videoProvider`. У встроенных результатов исходного URL нет, а временный URL может истечь раньше.


## Ограничения

- **По умолчанию xAI**: без `videoProvider` генерация видео использует API xAI Grok Imagine Video; другой бэкенд должен реализовать тот же асинхронный API
- **Асинхронно**: генерация видео занимает 30-120 секунд
- **Одно видео на один вызов**: каждый вызов `video_gen` создаёт одно видео
- **Совместим с Image Bridge**: оба моста можно включать одновременно
- **Приоритет web search**: если для хода активен web search sidecar (не-`runTurn` адаптер),
  video bridge пропускается — одновременно они не работают. Для диагностики в логах пишется
  `console.warn`.
- **Таймаут покрывает submit + poll**: бюджет `videoTimeoutMs` начинает отсчитываться ещё до
  отправки job, поэтому submit-вызов (60 с) и последующий polling делят один и тот же дедлайн.
