Это руководство проведёт вас от новой установки до первого запроса из используемого инструмента программирования. Шаги 1 и 2 общие для всех, а шаг 3 содержит отдельные инструкции для каждого инструмента. На [странице поддержки клиентов](/ru/reference/client-support/) перечислены инструменты и способы их подключения.

## Автономный бинарный файл (без npm)

Можно также использовать архив с бинарным файлом `ocx` и рантаймом Bun без npm.
Распакуйте его, оставив каталог `gui/dist` рядом с бинарным файлом, и выполните `./ocx start`.

## 1. Запустите мастер настройки

```bash
ocx init
```

`ocx init` проведёт вас по следующим шагам:

1. **Выбор провайдера** — выберите один из 106 встроенных пресетов реестра или `custom`, чтобы
   ввести базовый URL и адаптер вручную.
2. **API-ключ** — вставьте ключ или сошлитесь на переменную окружения вида `${ANTHROPIC_API_KEY}`.
3. **Модель по умолчанию** — для провайдеров с ключом, локальных и `custom` примите значение из
   пресета или введите id модели.
4. **Порт прокси** — по умолчанию `10100`.
5. **Внедрить в Codex?** — при обычной loopback-настройке opencodex добавляет корневой
   `openai_base_url` в `$CODEX_HOME/config.toml` (по умолчанию `~/.codex/config.toml`), чтобы
   встроенный провайдер `openai` в Codex указывал на прокси. При привязке к удалённым/LAN-адресам
   вместо этого используется отдельная запись провайдера с заголовком API-аутентификации.
6. **Установить shim автозапуска?** — если включено, при запуске `codex` сначала выполняется
   `ocx ensure`.

Результат сохраняется в `$OPENCODEX_HOME/config.json` (по умолчанию `~/.opencodex/config.json`).

:::note[Записи rollout GPT-5.6]
Текущий стабильный релиз добавляет GPT-5.6 Sol/Terra/Luna для passthrough ChatGPT, OpenAI по
API-ключу, OpenRouter и экспериментального адаптера Cursor. Они работают только тогда, когда у
соответствующего вышестоящего аккаунта есть доступ. Пресеты OpenAI по API-ключу и OpenRouter
заявляют используемое контекстное окно в 922 000 токенов; Cursor сохраняет собственные метаданные
адаптера.
:::

## 2. Запустите прокси

```bash
ocx start            # defaults to port 10100
ocx start --port 8080
```

При запуске opencodex:

- записывает свой PID в `~/.opencodex/ocx.pid` (и отказывается запускаться повторно),
- обнаруживает живые модели там, где провайдер это поддерживает, и **синхронизирует нативные и
  маршрутизируемые записи в каталог моделей Codex**,
- слушает `http://localhost:<port>/v1`.

Если запрошенный порт занят, `ocx start` останавливается и сообщает, какой процесс его удерживает:
если там отвечает opencodex, сначала выполните `ocx stop`; либо запустите прокси на свободном порту
через `ocx start --port <port>`. Команда не переходит на другой порт сама — раньше из-за этого два
прокси продолжали работать одновременно, а Codex перенаправлялся на более новый.

Проверьте:

```bash
ocx status
ocx gui       # open the dashboard on the live port
```

## 3. Подключите свой инструмент

Выберите инструкции для своего инструмента. Можно подключить несколько инструментов: они используют общие провайдеры и модели.

### Codex

Если на шаге 1 вы приняли приглашение Codex, теперь он прозрачно взаимодействует с opencodex. Если вы отклонили приглашение или настройка завершилась из-за существующей конфигурации, включите переключатель Codex на странице **Connect** панели перед запуском Codex; в разделе [Интеграция Codex](/ru/guides/codex-integration/) описаны изменения и их отмена.

```bash
codex "Refactor this function for readability"
```

Чтобы обратиться к конкретной маршрутизируемой модели, используйте форму `provider/model`,
которую показывает селектор модели в Codex:

```bash
codex -m "anthropic/claude-opus-5" "Explain this stack trace"
codex -m "ollama-cloud/glm-5.2"      "Write a SQL migration"
```

### Claude Code

При установленном CLI `claude`:

```bash
ocx claude
```

`ocx claude` запускает прокси, если он не работает, и запускает Claude Code с окружением, направленным на opencodex. Дополнительные аргументы передаются дальше. Значения уровней по умолчанию, другие способы запуска и отключение описаны в [Claude Code](/ru/guides/claude-code/).

### Claude Desktop

```bash
ocx claude desktop
```

При новой установке команда настраивает профиль шлюза для всего приложения. Если установка уже использует режим first-party, он сохраняется; выполните `ocx claude desktop apply --gateway`, чтобы явно переключить режим. Режим first-party сохраняет подключение Desktop к claude.ai и маршрутизирует только вкладку Code; см. раздел о режимах Claude Desktop в [Claude Code](/ru/guides/claude-code/).

После смены режима полностью закройте и снова откройте Claude Desktop.

### Grok Build

При локальном прослушивании, если существует `~/.grok`, команда `ocx start` регистрирует видимые модели в `~/.grok/config.toml`. Выберите модель `ocx-*` в Grok Build. Удалённые конфигурации и управляемый блок описаны в [Grok Build](/ru/guides/grok-build/).

После добавления провайдеров или моделей выполните `ocx ensure` или перезапустите прокси, чтобы Grok Build их увидел.

### Другие инструменты

Инструменты с управляемой интеграцией (OpenCode, Pi, Qoder, WorkBuddy, Kilo, Cline, T3 Code и другие) подключаются на странице **Connect** панели или командой:

```bash
ocx integration client enable --client <id>
```

Файлы конфигурации инструментов и время вступления изменений в силу описаны в разделе [Интеграции](/ru/guides/integrations/). Любой другой инструмент с поддержкой пользовательского адреса может использовать совместимый с OpenAI базовый URL `http://localhost:10100/v1` или базовый URL Anthropic `http://localhost:10100`.

## Выбор моделей подагентов (опционально)

В свежей конфигурации в селекторе подагентов Codex представлены пять нативных моделей: `gpt-5.5`,
`gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna` и `gpt-6-astra`. Откройте `ocx gui`, чтобы
заменить или переупорядочить до пяти нативных или маршрутизируемых моделей. В панели управления
также можно задать одну предпочитаемую модель подагента и уровень рассуждений. Раздел
[Поверхность подагентов](/guides/sub-agent-surface/) поможет выбрать v1/base/v2 и понять, когда
применяются guidance, нативные значения по умолчанию и fallback.

## Вход в аккаунт вместо вставки ключа

Некоторые провайдеры поддерживают полноценный вход в аккаунт (OAuth с автообновлением):

```bash
ocx login xai          # or: anthropic, kimi, kiro, google-antigravity, cursor
ocx logout xai
```

Самому OpenAI ключ **не нужен** — провайдер по умолчанию напрямую пересылает ваши существующие
учётные данные `codex login` (см. [Провайдеры](/guides/providers/)).

## Остановка и восстановление

```bash
ocx stop          # stop the proxy and restore native Codex
ocx restore       # restore native Codex without stopping (alias: ocx eject)
ocx restore back  # route Codex through the still-running proxy again
```
