## 原生登录不同于 Pool 选择

在 **Codex Set → Multi-auth** 中，打开主账户卡片正下方独立的 **Native main login** 面板内的 **Manage main login**。Providers 账户工作区的主卡片旁也有同一面板。它管理实际的 Codex 登录，而不是为下一个 Pool 请求选择账户。它不会新增 Integrations 标签页，也不会替换现有的 Pool 控件。

显示的 **Effective CODEX_HOME** 属于 OpenCodex 服务器。使用远程仪表盘时，它可能与浏览器位于不同计算机。**Registered active profile** 是加密配置文件存储中记录的所有者；切换前，服务器会验证实际登录。因此，在 OpenCodex 外部更改登录可能导致所有权不匹配错误，而不会被静默覆盖。

## 保存与切换

使用 **Save current as profile** 注册当前应用登录。如果该登录已经注册为活动配置文件，此操作会更新其标签，不会登记新账户。切换配置文件需要受支持的文件凭据存储和可用的操作系统密钥存储。诊断代码会解释控件不可用的原因；不要通过把 Pool 凭据复制到原生登录文件来绕过密钥存储或所有权错误。当主卡片现有的原生设备重新认证操作正在进行时，面板会被禁用。

在已存储的非活动配置文件旁选择 **Switch**。核对目标标签和服务器端主目录，停止使用该主目录的原生 Codex，然后勾选停止确认并提交。确认前不会发送凭据变更。提交前面板会重新读取当前主目录、活动所有者和恢复状态。如果状态发生变化，请查看新状态并再次确认。现有后端仍负责锁、进程检查、排空进行中的请求、激活和回滚。

成功后，按照显示的重启要求，用该主目录重新打开原生 Codex。面板会重新读取配置文件状态并刷新现有账户控制器。它不会调用 Pool 选择或配置变更，也不会编辑提供商密钥、任务或历史记录。现有后端仍会协调原生 `__main__` 身份，与 CLI 工作流相同。

## 恢复与先前的配置文件

以下是不同的操作：

- **Recover interrupted change** 用于协调未完成的后端事务。**Restore pending transaction** 请求回滚该事务。两者都需要单独确认 Codex 已停止。即使损坏的配置文件列表无法读取，只要诊断报告有待处理的恢复状态，这些控件仍可使用。
- 成功切换后，**Return to previously displayed** 会通过常规且需确认的切换流程选中切换前显示的配置文件。此快捷方式仅保存在页面内存中，并受主目录和预期活动所有者约束；页面重新加载或代理/所有者变化后便会消失。API 不返回事务来源，因此它不是经服务器验证的撤销日志：另一位操作者可能在预检读取与你的切换之间更改登录。重新加载后，请直接选择需要的已保存配置文件。

网络错误不能证明写入失败或已回滚。分发变更后，即使响应丢失，面板也会重新读取服务器状态，且绝不会自动重试。如果刷新失败，成功的变更不会被报告为已撤销。再次操作前，请刷新并检查诊断。现有的 `ocx account main doctor` 命令提供服务器端诊断。

## 本阶段的范围

此面板通过现有的 `/api/native-main-profiles` 边界列出、注册、切换和恢复配置文件。它不会启动登录进程或暴露暂存写入令牌。添加另一个原生登录仍使用现有的 `ocx account main add` CLI 工作流；浏览器登记是 issue #3417 的另一项后续工作。当前主槽位现有的设备重新认证是不同的工作流，不会被此面板替换。

配置文件数据不会写入浏览器存储。客户端只投影公开字段，显示允许列表中的错误代码而不是原始服务器消息，并使用应用现有的认证请求封装。后端的管理认证、GUI 会话/CSRF 和路由准入检查保持不变。
