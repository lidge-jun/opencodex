## 네이티브 로그인과 Pool 선택은 다릅니다

**Codex Set → Multi-auth**에서 메인 계정 카드 바로 아래의 별도 **Native main login** 패널에 있는 **Manage main login**을 여세요. 같은 패널이 Providers 계정 작업 공간의 메인 카드 옆에도 있습니다. 여기서는 다음 Pool 요청에 선택할 계정이 아니라 실제 Codex 로그인을 관리합니다. Integrations 탭을 추가하거나 기존 Pool 제어 기능을 대체하지 않습니다.

표시되는 **Effective CODEX_HOME**은 opencodex 서버의 경로입니다. 원격 대시보드를 사용한다면 브라우저와 다른 컴퓨터일 수 있습니다. **Registered active profile**은 암호화된 프로필 저장소에 기록된 소유자입니다. 서버는 전환 전에 실제 로그인을 확인합니다. 따라서 opencodex 밖에서 로그인을 바꾸면 조용히 덮어쓰는 대신 소유자 불일치 오류가 날 수 있습니다.

## 저장과 전환

**Save current as profile**로 기존 앱 로그인을 등록하세요. 이미 등록된 활성 로그인이라면 새 계정을 등록하지 않고 이름만 갱신합니다. 프로필 전환에는 지원되는 파일 자격 증명 저장소와 사용 가능한 운영체제 키 저장소가 필요합니다. 제어 기능을 사용할 수 없는 이유는 진단 코드로 표시됩니다. 키 저장소나 소유권 오류를 우회하려고 Pool 자격 증명을 네이티브 로그인 파일에 복사하지 마세요. 메인 카드에서 기존 네이티브 기기 재인증 작업이 진행 중일 때는 패널이 비활성화됩니다.

저장된 비활성 프로필 옆의 **Switch**를 선택하세요. 대상 이름과 서버 쪽 홈을 확인하고, 그 홈을 쓰는 네이티브 Codex를 중지한 다음, 중지 확인란을 선택하고 제출하세요. 확인 전에는 자격 증명 변경 요청을 보내지 않습니다. 패널은 제출 직전에 현재 홈, 활성 소유자, 복구 상태를 다시 읽습니다. 상태가 달라졌다면 새 상태를 검토하고 다시 확인하세요. 잠금, 프로세스 확인, 진행 중인 요청 배출, 활성화, 롤백은 기존 백엔드가 최종적으로 처리합니다.

성공한 뒤에는 표시된 재시작 요구 사항에 따라 해당 홈에서 네이티브 Codex를 다시 여세요. 패널은 프로필 상태를 다시 읽고 기존 계정 컨트롤러를 새로 고칩니다. Pool 선택·설정 변경을 호출하거나 프로바이더 키, 작업, 기록을 수정하지 않습니다. 기존 백엔드는 CLI 워크플로와 마찬가지로 네이티브 `__main__` ID를 계속 조정합니다.

## 복구와 이전 프로필

다음은 서로 다른 작업입니다.

- **Recover interrupted change**는 완료되지 않은 백엔드 트랜잭션을 조정합니다. **Restore pending transaction**은 그 트랜잭션의 롤백을 요청합니다. 둘 다 별도의 중지 확인이 필요합니다. 손상된 프로필 목록을 읽지 못하더라도 진단 결과에 복구 대기 상태가 있으면 이 제어 기능을 사용할 수 있습니다.
- 전환에 성공한 뒤 **Return to previously displayed**는 일반적인 확인 절차를 거쳐 전환 전에 표시되던 프로필을 선택합니다. 이 바로가기는 홈과 예상 활성 소유자에 묶여 페이지 메모리에만 남으며, 페이지를 새로고침하거나 프록시 또는 소유자가 바뀌면 사라집니다. API는 트랜잭션 출처를 반환하지 않으므로 서버가 검증한 실행 취소 기록이 아닙니다. 사전 확인과 전환 사이에 다른 운영자가 로그인을 바꿨을 수 있습니다. 페이지를 다시 연 뒤에는 원하는 저장 프로필을 직접 선택하세요.

네트워크 오류만으로 쓰기에 실패했거나 롤백되었다고 단정할 수 없습니다. 패널은 응답을 잃은 경우까지 포함해 변경 요청을 보낸 뒤 서버 상태를 다시 읽으며 자동 재시도하지 않습니다. 새로고침이 실패해도 성공한 변경을 취소된 것으로 보고하지 않습니다. 다음 작업 전에 새로고침하고 진단 결과를 확인하세요. 기존 `ocx account main doctor` 명령은 서버 쪽 진단 정보를 제공합니다.

## 이 단계의 범위

이 패널은 기존 `/api/native-main-profiles` 경계를 사용해 기존 프로필을 나열·등록·전환·복구합니다. 로그인 프로세스를 실행하거나 준비 단계의 기록기 토큰을 노출하지 않습니다. 다른 네이티브 로그인 추가는 기존 `ocx account main add` CLI 워크플로에서 합니다. 브라우저를 통한 등록은 이슈 #3417의 별도 후속 작업입니다. 현재 메인 슬롯의 기존 기기 재인증은 다른 워크플로이며 이 패널로 대체되지 않습니다.

프로필 데이터는 브라우저 저장소에 쓰지 않습니다. 클라이언트는 공개 필드만 투영하고, 원시 서버 메시지 대신 허용 목록에 있는 오류 코드만 표시하며, 애플리케이션의 기존 인증 fetch 래퍼를 사용합니다. 백엔드의 관리 인증, GUI 세션/CSRF, 라우트 수용 검사는 그대로입니다.
