---
title: Codex Upload Reduction
description: Optional incremental WebSocket uploads and lossy historical context slimming.
---

These default-off top-level options apply to native ChatGPT Codex requests. If you save a change with `ocx config set`, it takes effect when the running proxy adopts the updated config or after a restart. `/api/sync` reads a separate snapshot for client integration. See [provider configuration](/reference/configuration/providers/) for other settings.

| Field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `codexWsIncrementalUpload?` | `boolean` | `false` | Experimental native ChatGPT Codex upload reduction. Implies cross-turn socket reuse for callers with a resolved API key principal. Keyless loopback requests use one-shot sockets and send full creates. Each named provider route has its own socket scope. After an acknowledged completed response, an exact matching input prefix can be replaced by `previous_response_id` and only new input items. Clients may keep using HTTP/SSE; `websockets` controls only client-facing upgrades. History/settings/account/route changes and expired sockets require a full create. If the backend explicitly rejects a proxy-synthesized continuation ID as missing before any response activity, the proxy resends the retained full request once under the same caller and dispatch guards; caller-supplied IDs and unknown delivery are never replayed by this recovery. If that resend is refused by the request's send budget, workflow ceiling, or spend admission, the client receives that original `previous_response_not_found`; its next full-history request is sent as a full create. With this flag, a provider whose explicit egress is an HTTP proxy sends Codex WebSocket traffic through that proxy instead of downgrading to HTTP/SSE; SOCKS, direct overrides and custom executors keep their existing fallback. Idle sockets are retained for up to 10 minutes and 50 minutes total age; the 32-socket pool and 32-exchange per-socket bounds remain. |
| `upstreamHistorySlim?` | `"off" \| "codex"` | `"off"` | Optional **lossy** native Codex history policy. Before the latest user message, inline images larger than 1 KiB become text placeholders and tool output text larger than 32 KiB is shortened to its first 2 KiB and last 1 KiB. Current-turn items, local history, remote image URLs and file references remain intact. This does not guarantee that each image is uploaded exactly once, and the model cannot inspect an omitted old image on a full replay. Use `off` when historical image detail must remain available. HTTP/SSE creates apply this setting on its own. The `/responses/compact` endpoint receives the full context. Ordinary upstream WebSocket creates are slimmed only when `codexWsIncrementalUpload: true` is also set. |
