# CLI management and discovery

`src/cli/` contains the terminal management interface. Process ownership, startup, stop and service contracts remain in [Runtime](runtime.md); this document owns command discovery, help, management-client presentation and the generated operating reference.

## CLI readiness diagnostics

`src/cli/status.ts` retains connection transport in the status JSON. Link clients identify Remote Link Home in the banner and connection line. They read supported Hub state through the identity-checked local Child without a CLI credential, retain owner-bound cache fallback on transport errors, and report standalone Home role absence without obsolete Hub cache. Hub clients retain their existing remote provider and login report.

Catalog-derived reasoning-level diagnostics are escaped only at the human-output boundary, which `src/cli/runtime-api.ts` owns alongside the human/JSON print split. Every CLI path that prints a hub-supplied catalog value renders it there: the first-time refusal in `src/cli/connect.ts` and the connected `ocx sync` refusal in `src/cli/dispatch.ts`. C0/C1 controls, DEL, and Unicode line/paragraph separators print as visible hexadecimal escapes; structured status retains the exact reason, and a rendered failure keeps the domain error as its `cause`. The ready/unverified/incompatible classification and exit policy are unchanged. `src/cli/capabilities-command.ts` rejects leftover positional arguments, unknown or repeated flags, and blank route filters with exit 64 before emitting a capability index; a valid unmatched route remains exit 4. `printData` in `src/cli/runtime-api.ts` escapes each human-output line at the shared renderer, including role and delegation-model suggestion rationale. JSON output retains the exact original values. `src/cli/export-command.ts` passes native serialized documents as individual lines so their multiline layout is preserved. `tests/cli/cli-headless-parity.test.ts` checks both suggestion paths independently from their parsed JSON output; `tests/cli/cli-export-command.test.ts` covers export framing. `src/cli/hub-disable.ts` implements `ocx hub disable` as one fresh validated config mutation, with explicit `--client-key <id>` selection for `--revoke-clients` because saved keys lack immutable client origin; names never select keys and non-hub roles refuse. It projects only secret-redacted metadata and supervisor/external-publishing advice, without restarting anything. `src/cli/observe.ts` reports no matches for an empty filtered human log window while preserving JSON/JSONL; `src/server/request-log-filter.ts` matches whole bare IDs or provider/model pairs within a single row/attempt before pagination.

`src/cli/desktop-runtime-guidance.ts` names verified Desktop supervision of the target for
duplicate starts and accepted restart requests. Ordinary stop warns on stderr that Desktop
may start the proxy again after backoff and directs the user to Stop Proxy or Quit in the
OpenCodex menu. `stop --json` does not probe or print this guidance. Acceptance is not
replacement health proof: lifecycle decisions, attestation and exit codes stay authoritative,
and a known supervised target never earns a competing CLI recovery start. Command guard
continuity follows [runtime ownership](runtime.md#background-service-runtime-ownership).

The export roster and full help include `gentle-shell`, with a persistent-home and
Pi link/shared-home remedy; this adds a client identity, not a new command or flag.

## Head and help navigation

`src/cli/codex-launch-policy.ts` authorizes fresh credentials by explicit argument, environment and configuration allowlists. Only interactive and `exec` modes qualify; restored sessions and every config/profile/provider-selection override withhold fresh credentials. The switches are `--no-daemon`, `--json`, `--ephemeral`, `--skip-git-repo-check`, `--no-alt-screen`, `--full-auto`, `--dangerously-bypass-approvals-and-sandbox`, `--search`; one-value options are `--model`/`-m`, `--sandbox`/`-s`, `--ask-for-approval`/`-a`, `--image`/`-i`. Short clusters and missing values refuse. Only model/provider selection, model reasoning/verbosity strings, approval/sandbox strings, the matching root URL and disabled system-proxy feature are accepted in the home configuration. Alternate providers, MCP servers (including stdio inheritance), hooks and unknown keys refuse. Every token-variable reference outside the verified provider is refused, even in an unselected profile. Nonempty unknown CODEX/OpenAI/Azure environment controls refuse. Additional authentication, system, managed, requirements and project layers are not authorized. Refusals preserve argv and explicit credentials and print a value-free stderr note.

`src/cli/codex-launch-ownership.ts` checks current-user ownership of the canonical home and config, rejects POSIX group/other writes and Windows DACL mutation grants outside current user/SYSTEM/Administrators, and rejects unsafe ancestor replacement rights. Windows system paths come from the CommonApplicationData known folder; ancestor ownership also permits TrustedInstaller. macOS checks forced CoreFoundation preferences. Read/inspection errors deny. The key is supplied only when configuration and its namespaces are protected from other principals; the current user, SYSTEM/Administrators and the documented OS authorities are trusted. Same-user processes are trusted: an actor with this user's write access can already read this user's OpenCodex key file. Same-user configuration replacement between verification and native startup is outside this threat model; the check does not establish immutable startup configuration or isolate privileged processes. Regression coverage is in `tests/codex-integration/codex-launcher-admission.test.ts`.

Same-file project aliases additionally require ownership/ACL inspection of the lexical entry, every ancestor and every intermediate symlink target. The Windows checker reuses its ACL policy in a path-chain mode, including the reparse entry itself; POSIX permits only current-user/root ownership and no group/other writes, with sticky directories protecting current-user-owned entries. macOS opens lexical symlinks with O_SYMLINK alone and non-links with O_NOFOLLOW, retaining NONBLOCK/CLOEXEC and directory-only flags where applicable. Descriptor dev/ino/type must match the earlier lstat before fd-based ACL inspection; replacements and inspection errors refuse, and every opened descriptor closes. Unknown or failed inspection withholds the token with reason `project` before reading it. `tests/codex-integration/codex-launcher-env.test.ts` covers protected home aliases, writable alias entries/parents/ancestors/redirects and inspection failure; `tests/codex-integration/codex-launcher-darwin-identity.test.ts` models XNU link-open semantics and replacements, and `tests/codex-integration/codex-launcher-darwin-acl.test.ts` includes native Darwin protected-symlink admission.

`src/cli/codex-launch-diagnostics.ts` maps each fresh-key withholding reason to one fixed stderr line without shell commands, credential values, key-file paths, config contents or exception text. Default Windows ProgramData rights remain unsafe even when OpenAI/Codex is absent. The diagnostic states that the system Codex configuration folder under ProgramData must exist and be writable only by Administrators/SYSTEM, with ancestors protected against replacement by other users. It requests administrator policy review and states that opencodex never changes ACLs itself; no provisioning command is supplied. Users can instead supply their own key by exporting OPENCODEX_API_AUTH_TOKEN, which the launcher leaves untouched. Existing system configuration still refuses automatic credentials. Tests in `tests/codex-integration/codex-launcher-diagnostics.test.ts` cover command-free, one-line non-disclosure, real missing/writable Windows namespace refusals and explicit credential preservation. Public requirements and the explicit-key alternative live in the [CLI reference](../docs-site/src/content/docs/reference/cli/agents.md#ocx-codex-codex-args).


For fresh credentials, the launcher resolves a native literal `CODEX_HOME` once and passes the canonical absolute directory both to the destination verifier and to the child. Missing, unreadable or non-directory homes and ambiguous Windows home casing withhold credentials. Any nonempty inherited HTTP(S)/ALL proxy variable, matched case-insensitively, suppresses token reads irrespective of NO_PROXY; denied and inherited-token launches preserve their environment. Successful injection adds both allowed loopback IPs to identical child NO_PROXY/no_proxy values while preserving prior bypass entries, covering default OS proxy discovery. Configured `features.respect_system_proxy` and feature-changing argv suppress loading because system-selected routes can ignore bypasses.

`src/cli/codex-launcher.ts` implements `ocx codex` without rewriting routing. Native/foreign routes pass through; local/unknown routes attempt startup and warn on failure. Fast paths skip startup/token loading. A matched wrapper uses its backing directly. Unknown state, including a throwing inspector, requires a separate bypass check via `src/cli/codex-launch-command.ts`; managed Windows CMD wrappers require complete generated-template equality before the selected absolute path executes with bypass. Obsolete, unreadable or ambiguous wrappers and lookup errors refuse launch without exception contents. A missing executable instead reports the Codex install hint, including on help/version fast paths. This content check does not establish Windows backing provenance or prevent concurrent replacement. `src/cli/codex-launch-auth.ts` separately requires a parsed managed transport block matching this installation's loopback listener or persisted local client connection; names/comments alone grant no token. Profiles, distinct project layers scanned through the filesystem root, destination-changing argv and environment overrides prevent automatic loading. An existing ancestor config is excluded only when its realpath matches the home config; a different file or failed identity resolution refuses. Token-file overrides and management-token collisions remain refused; user exports are preserved. No token enters argv or diagnostics.

The `codex` namespace forwards all help arguments unchanged; `ocx help codex` retains wrapper help. It skips root shim repair so the routing-aware launcher owns the handoff. Every handoff, including help/version and passthrough, awaits the [execution trust contract](clients/chatgpt-desktop.md#codex-app-execution-trust) for the selected backing and spawns the returned invocation. On macOS, CLI handoffs verify any enclosing `.app` at the canonical target location, including renamed bundles and symlink targets; nested apps retain the outer bundle root. Fast paths bypass startup and credential loading, not executable validation. The hidden `internal codex-exec-target` helper returns a single verified path for the generated app-server launcher; its strict `--bundle-root` mode retains the discovered root independent of bundle name and refuses malformed roots without falling back to generic classification. It skips root shim auto-repair even on malformed arguments, and stays outside public capability discovery.
Forwarded `-c`/`--config` and `-p`/`--profile` overrides make effective routing unverified for automatic service-token injection. They retain original argv and user-exported credentials but never load a new token from disk. Single-word prompts require `--` so they cannot select an unknown native subcommand. Missing system files also require a protected namespace: the closest existing directory must prevent another user from creating the missing layer, and its ancestors must prevent replacement. A normal Windows ProgramData directory that grants Users directory creation cannot authorize an absent OpenAI/Codex namespace; the launcher withholds credentials without creating or changing that directory. macOS opens each validated entry without following its final link (O_SYMLINK for the link entry itself), keeps dev/ino as bigint and requires descriptor dev/ino/type to match its original lstat, and reads its ACL with acl_get_fd_np. Only NULL with immediately captured ENOENT on this descriptor query means no extended ACL; open/stat/identity/close failures and every other NULL/error refuse. Every opened descriptor closes in finally. For a present ACL it validates and enumerates every entry through the documented -1/EINVAL terminator. Deny-only and read-only allow entries are accepted; any allow granting write/add-file, append/add-subdirectory, delete, delete-child, attribute, extended-attribute, security or ownership mutation refuses regardless of earlier denies. Unknown tags and FFI/enumeration failures refuse. Forced managed-preference checks remain mandatory. Pure policy and Darwin-gated native ACL coverage lives in `tests/codex-integration/codex-launcher-darwin-acl.test.ts`; modeled IO regressions for all three walks live in `tests/codex-integration/codex-launcher-darwin-identity.test.ts`. Tests model a protected empty machine namespace inside their private fixture; they do not modify real system configuration. Windows fixtures probe ancestor ownership before positive assertions; an unavailable protected location requires a proved ownership refusal and an explicit skip reason. Negative mutations and no-token/zero-read assertions execute even with unsafe ancestors; credential-file negatives bypass destination verification independently. Native checks use production defaults.

## Keyless CC-Switch provider import

`src/cli/provider-cc-switch-import.ts`, `src/providers/cc-switch-import-bytes.ts`, `src/providers/cc-switch-import-source.ts` and `src/providers/cc-switch-import.ts` implement `ocx provider import-cc-switch`. Its primary security guarantee is structural: the importer projects values only from an explicit allowlist of non-secret metadata fields (provider IDs, app types, base URLs, wire dialects and default models); source and embedded-config bytes are read transiently while secret fields, free-text display names, and TOML comments are skipped at the byte level and never decoded into strings, written, or logged. Narrow base-URL grammar (`http(s)://host[:port]` with an empty path or 1–4 lowercase `[a-z0-9._-]` API path segments such as `/v1`, `/api/v1`, or `/compatible-mode/v1`) and identifier/model syntax checks act strictly as defense in depth before `TextDecoder.decode` and return non-echoing invalid-entry categories (`invalid_base_url`, `disallowed_metadata`); transient byte buffers are zeroed in `finally`. The source file is opened once with `O_RDONLY | O_NOFOLLOW | O_NONBLOCK`, format-detected by pure 16-byte header comparison without string decoding, verified before and after reading by `fstatSync` and `lstatSync` identity checks (`dev`, `ino`, `uid`, `gid`, `mode`, `size`, `mtimeMs`), refused fail-closed for SQLite when `fstatSync(fd).nlink > 1` or when a sibling `-wal` or `-journal` file is non-empty or unreadable, and deserialized for SQLite read-only in memory via `Database.deserialize` without reopening user pathnames or writing temporary snapshots. Destinations are validated with `providerBaseUrlConfigError` and `providerDestinationConfigError`, and `--apply` prints every imported ID, model, and destination URL before writing the journal or `config.json` (to `stdout` in text mode and `stderr` in `--json` mode, plus `trustNotice` in the JSON payload).

Preview writes nothing. Apply and restore refuse on a link Child or while a proxy is running, acquire `acquireOwnershipMutationLease`, and run inside `withConfigMutationLockSync` and `mutatePersistedConfig`. Each apply generates a per-transaction UUID `importId` embedded in `providers.<name>.note` and writes `cc-switch-provider-import-journal.json` via `atomicWriteFileStreamed`. Repeated apply is refused while a committed or published journal exists; a post-publication throw retains the journal whenever any entry with `importId` landed on disk. Restore inspects `auth.json` read-only at the byte level (without decoding OAuth tokens, failing closed if unreadable or malformed) and rechecks fingerprint, `importId` note, `isProviderReferencedInConfig` and `validateConfigCandidate` on every rebase attempt, removing only unedited, unreferenced imported entries. Coverage: `tests/providers/cc-switch-import.test.ts` and `tests/cli/cli-provider-cc-switch-import.test.ts`.
