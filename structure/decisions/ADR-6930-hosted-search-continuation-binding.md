# ADR-6930 — decision recorded under "Hosted-search continuation binding"

- Contract owner: [providers-and-adapters.md](../providers-and-adapters.md#hosted-search-continuation-binding)

## Decision record

- Purpose and intent: Let an explicitly selected Codex Responses Lite continuation carry useful metadata from old hosted-search history when there is no same-scope bridge call/result to restore.
- Prior constraints and evidence: Official Codex 0.161.0 omits hosted model tools on its Lite path and can expose client-executed `web.run` through standalone search. It still defines and replays `WebSearchCall` history. The report in [openai/codex#51962](https://github.com/openai/codex/issues/51962) records a successful default new Sol conversation, failure compacting restored hosted history, success after removing those hosted cells, and a raw hosted-history request that succeeds when the matching hosted tool is declared. This supports a Lite/history compatibility problem, not a universal hosted-schema ban or proof that every ordinary Lite request fails. Public Responses documentation continues to describe [hosted web-search output](https://developers.openai.com/api/docs/guides/tools-web-search#output-and-citations).
- Alternatives considered: Keep the original all-canonical ordinary projection; infer Lite from model names, subscription authentication or absent hosted declarations; require a separate provider opt-in; or narrow the existing policy to explicit current-request Lite intent. A narrower action/query repair would retain more structure but cannot represent an old hosted call as a client-executed Lite tool.
- Chosen approach: The contributor narrowed ordinary projection to the existing exact canonical ChatGPT `/responses` destination and explicit Lite intent after bridge restoration and normalization. The final HTTP header's literal `true`/`false` wins; otherwise literal `true` in valid string-map frame metadata is the fallback, matching existing WS preparation. Missing, non-Lite or unrecognized effective intent keeps structural hosted history. No transport signal is created or rewritten by this decision.
- Reason for this choice: The current request supplies a protocol-specific boundary without guessing where historical cells originated or assuming every model/account uses Lite. Keeping non-Lite and unknown requests structural avoids imposing a lossy policy on compatible hosted-tool continuations. Compared with a new provider switch, the existing Lite signal ties the repair to the client's selected protocol; it does not prove that loss is necessary for every Lite request.
- Consequences and limitations: Lite still defaults to lossy, bounded, untrusted reference notes for unreferenced remaining hosted cells. Same-input references and same-scope bridge restoration keep their existing exemptions/order; public API, native compaction and portable/routed summary triggers are unchanged. The original renderer enhancement preserves allowlisted top-level sources in portable summaries as well. This record explains the contributor's authorized narrower implementation, not project-owner acceptance or readiness. Fixture tests establish serialization behavior only; live ordinary HTTP/WS acceptance, all upstream errors and backend policy remain unverified.
