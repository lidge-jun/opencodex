# Microsoft 365 Copilot

The repository owner has granted a canonical-preset policy exception; the independent maintainer security re-review passed on implementation head `359a57431b` (October 28, 2026). The [public evidence section](../../docs-site/src/content/docs/guides/m365-copilot.md#evidence-and-admission-status) distinguishes Microsoft's documented Graph API from this observed private ChatHub/bootstrap contract.

`src/providers/registry/entries-core.ts` registers the opt-in, non-featured `m365-copilot` OAuth provider with live account discovery and an empty offline roster. It is separate from `github-copilot`. `src/providers/m365-copilot-models.ts` keeps old request aliases compatible and accepts Microsoft's native selector IDs so new versions need no alias-table update. A selector is not evidence of an underlying model identity.

`src/providers/m365-copilot-discovery.ts` parses only the main `bizchatAsAgentGpt.clientPreferences.modelSelectorMetadata` from Microsoft's authenticated chat-page bootstrap. It validates the work-account identity, flattens nested groups, deduplicates leaves and rejects malformed or excessive rows. Researcher and other agent rosters stay excluded. Daily quota-disabled entries remain in the entitlement roster. `src/codex/catalog/m365-copilot-models.ts` reads that page at the fixed Copilot origin through shared outbound policy, limits the body to 2 MiB, and binds TTL/stale cache rows to the captured account and web cookie. Failed reads never advertise the old alias table. Existing new-model policy and operator selections govern visibility.

`src/oauth/m365-copilot.ts` uses Microsoft's documented M365 Chat Client identifier, organizational authorization authority, fixed nativeclient redirect, S256 PKCE and existing protected OAuth persistence/refresh. Scope is limited to profile, offline access and the Sydney chat read/readwrite permissions. It requests no Power Platform agent-management permission. Refresh is lazy-only. Error messages never include a code, token or token-endpoint body.

`src/providers/m365-copilot-discovery-fetch.ts` owns the shared fixed-origin authenticated roster read. `src/server/management/m365-copilot-provider-probe.ts` uses that same reader for dashboard connectivity testing; it reports real upstream success rather than accepting a cached catalog as connectivity evidence.

`src/oauth/m365-copilot-browser.ts` selects an installed supported default browser, with Firefox WebDriver BiDi and Chromium CDP capture. Each login owns an isolated temporary profile and a loopback-only control channel. The exact Microsoft callback and state are checked before consuming the code locally. `src/oauth/m365-copilot-web-session.ts` then loads the Copilot chat picker in that same window and captures only allowlisted Copilot web cookies. OAuth and web account identities must match. Cookies stay in the protected credential store and private catalog snapshots; account summaries never include them. Token refresh retains the same-account web session. Its independent expiry may require interactive login for fresh model discovery while chat-token refresh continues. The public login hint contains instructions and an empty URL, so CLI and management callers do not open a second browser. Cancellation/expiry closes the owned window, and cleanup retries bounded Windows profile-handle release. Firefox, Chrome and Edge are supported; this is not a headless or ordinary external-browser callback flow.

`src/adapters/m365-copilot.ts` owns the native turn. It reuses Chat tool lowering and output contracts through the adapter registry's semantic inheritance; it sends no Chat Completions HTTP request. The actual upstream transport is `src/adapters/m365-copilot/transport.ts`, a Bun WebSocket to the fixed Microsoft ChatHub origin. The socket follows provider proxy and bypass settings, and inherited global proxy settings including the bypass list; it refuses custom fetch executors. Tokens are never serialized into diagnostics, and the operator cannot redirect this transport to another origin. Shared physical-send admission is checked before the chat frame, and account/model/client/tool-bound conversation state is bounded and expired lazily.
Empty ChainOfThoughtSummary strings are not emitted as reasoning events: they carry no output and must not commit combo preflight before a quota refusal. Real reasoning and client output retain the ordinary commitment boundary. `tests/providers/m365-copilot-failover.test.ts` covers streaming/buffered quota hops, subsequent provider fallback and the real-reasoning hard stop.

Request-scoped executors must carry the provider-and-endpoint-bound native socket authority in `src/lib/provider-egress.ts`. The built-in request transport grants it only without a custom fetch executor, TLS replacement or dispatch override. HTTP egress transparency alone is insufficient. The adapter refuses opaque incoming executors with a safe 400 before image preparation, upload admission or socket dialing; the transport rechecks that authority and consumes the captured proxy and bypass list.

`src/adapters/m365-copilot/images.ts` preserves user and tool-result image parts before text lowering. It validates PNG/JPEG/GIF/WebP bytes, downloads remote images through the shared public-only pinned helper without credentials or redirects, and uploads to the fixed Microsoft UploadFile endpoint. Images become opaque ImageFile annotations on the matching conversation. At most four new images per turn and 5 MiB per image bound the upload workspace; its temporary serialization uses the shared provider_image_upload budget observation. Failures stop the turn rather than silently dropping an image. Conversation continuations upload only fresh images; replay/reset reattaches the required history. The shared picker has no per-model modality field, so catalog and registry declare text plus image for all chat selectors. This declaration describes the implemented attachment protocol, not per-model upstream discovery.

The transport validates and bounds SignalR frames, assembles text per bot message, preserves heartbeat/completion handling, reports quota/refusal errors and sends Stop on cancellation. Socket cleanup failures are reported without private transport details, and an undeliverable Stop remains a cancellation. Invalid tool JSON stays text; optional YAML/JSON parsing retains its explicit text fallback. Its answer collector participates in the shared translator budget described in [stream-buffer accounting](../transports/byte-accounting.md#stream-buffer-accounting). No Copilot Studio agents, remote action auto-confirmation, standalone HTTP compatibility server or browser automation dependency is included.

`src/adapters/m365-copilot/fenced.ts` and `src/adapters/m365-copilot/tools.ts` retain only the selected MIT tool grammar and baseline/relay/relay-batch framing. Tool names must belong to the declared catalog, custom/namespace identities are restored, and client results continue the same eligible conversation. Request history that is not an extension starts a fresh conversation. Copilot-generated speculative tool output is not treated as a real client result. The client retains execution ownership. The source notice is in `src/adapters/m365-copilot/LICENSE`.

`tests/providers/m365-copilot-security.test.ts` checks retargeted OAuth rows and runtime wire pins, and exercises Bun's real WebSocket constructor against a refusing loopback proxy while asserting that the loopback destination receives no direct connection. Both plain and TLS WebSocket attempts use HTTP CONNECT. Explicit and inherited SOCKS routes fail with a configuration error before dialing; the ChatHub socket supports HTTP(S) proxies only.

`tests/providers/m365-copilot-executor.test.ts` checks adapter-level request-executor refusal with zero destination connections and zero upload-admission calls. It also exercises successful native turns with no executor and with the built-in request executor, rejects HTTP-only or mismatched authority, and checks the captured route and bypass list.

`tests/providers/m365-copilot.test.ts` covers registration, selector rejection, PKCE/callback state, text assembly, bounded SignalR completion, tool continuation and destination/cancellation refusal. `tests/providers/m365-copilot-discovery.test.ts` covers live refresh, new selectors, grouping, trust boundaries, private cookie persistence and both browser protocol shapes. `tests/providers/m365-copilot-images.test.ts` covers image uploads, attachment framing, tool-result images, continuation reuse, validation, cancellation, destinations and image modality publication. Public setup and limitations are documented in `docs-site/src/content/docs/guides/m365-copilot.md`.
