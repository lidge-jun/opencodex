# Microsoft 365 Copilot

`src/providers/m365-copilot-models.ts` owns the maintained alias-to-ChatHub-selector mappings. `src/providers/registry/entries-core.ts` registers the opt-in, non-featured `m365-copilot` OAuth provider with a static catalog and text-only input declarations. It is separate from `github-copilot`. `src/providers/static-model-discovery.ts` prevents the catalog from becoming an authenticated HTTP models probe. Aliases are not evidence of an account entitlement or underlying model identity.

`src/oauth/m365-copilot.ts` uses Microsoft's documented M365 Chat Client identifier, organizational authorization authority, fixed nativeclient redirect, S256 PKCE and existing protected OAuth persistence/refresh. Scope is limited to profile, offline access and the Sydney chat read/readwrite permissions. It requests no Power Platform agent-management permission. Refresh is lazy-only. Error messages never include a code, token or token-endpoint body.

`src/oauth/m365-copilot-browser.ts` selects an installed supported default browser, with Firefox WebDriver BiDi and Chromium CDP capture. Each login owns an isolated temporary profile and a loopback-only control channel. The exact Microsoft callback and state are checked before consuming the code locally. The public login hint contains instructions and an empty URL, so CLI and management callers do not open a second browser. Cancellation/expiry closes the owned window, and cleanup retries bounded Windows profile-handle release. Firefox, Chrome and Edge are supported; this is not a headless or ordinary external-browser callback flow.

`src/adapters/m365-copilot.ts` owns the native turn. It reuses Chat tool lowering and output contracts through the adapter registry's semantic inheritance; it sends no Chat Completions HTTP request. The actual upstream transport is `src/adapters/m365-copilot/transport.ts`, a Bun WebSocket to the fixed Microsoft ChatHub origin. Tokens are never serialized into diagnostics, and the operator cannot redirect this transport to another origin. Shared physical-send admission is checked before the chat frame, and account/model/client/tool-bound conversation state is bounded and expired lazily.

The transport validates and bounds SignalR frames, assembles text per bot message, preserves heartbeat/completion handling, reports quota/refusal errors and sends Stop on cancellation. Its answer collector participates in the shared translator budget described in [stream-buffer accounting](../transports/byte-accounting.md#stream-buffer-accounting). No Copilot Studio agents, remote action auto-confirmation, standalone HTTP compatibility server or browser automation dependency is included.

`src/adapters/m365-copilot/fenced.ts` and `src/adapters/m365-copilot/tools.ts` retain only the selected MIT tool grammar and baseline/relay/relay-batch framing. Tool names must belong to the declared catalog, custom/namespace identities are restored, and client results continue the same eligible conversation. Request history that is not an extension starts a fresh conversation. Copilot-generated speculative tool output is not treated as a real client result. The client retains execution ownership. The source notice is in `src/adapters/m365-copilot/LICENSE`.

`tests/providers/m365-copilot.test.ts` covers registration, selector rejection, PKCE/callback state, text assembly, bounded SignalR completion, tool continuation and destination/cancellation refusal. Public setup and limitations are documented in `docs-site/src/content/docs/guides/m365-copilot.md`.
