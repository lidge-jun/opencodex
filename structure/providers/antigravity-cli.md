# Antigravity CLI Subscription

`antigravity-cli` (`src/providers/registry/entries-extended.ts`) drives Google's official Antigravity CLI (`agy`) headlessly in `stream-json` mode. Standard text and tool turns run through the in-process `AntigravitySessionPool` (`session-pool.ts` in `src/adapters/antigravity-cli/`), which retains up to `4` warm `agy` subprocesses (`90s` idle TTL) keyed by a SHA-256 signature over `baseUrl`, resolved `--model` slug, rendered `agent.md` rules, and serialized tool catalog; warm sessions park in `awaiting_tool_results` (resuming via `tool-results.jsonl`) or `idle_after_stop` (resuming via incremental `stdin` user frames) and fall back to a fresh spawn if an idle process exits before emitting output. Although `agy --conversation=<id>` can also resume across processes and hit prefix cache (`cache_read_tokens = 14,035` on turn 2 with a `>=16k`-token prefix), the adapter uses the in-process warm pool to avoid cold-starting `agy` and the isolated Bun MCP server (`190.9 ms` median `initialize` -> `tools/list` for a 200-tool catalog) on every turn. Requests carrying staged inline raster images or `textFormat` structured-output constraints take the single-shot `runCodingAgentTurn` (`src/adapters/coding-agent/turn.ts`) path. It is separate from the OAuth Cloud Code Assist `google-antigravity` provider and stores or injects no Google token.

## Credential ownership, prompt replacement, and turn isolation

`agy` reads the operator's signed-in Google account directly from the OS keyring (`%LOCALAPPDATA%\agy\bin\agy.exe` on Windows, `~/.local/bin/agy` on POSIX, or `PATH`). `src/adapters/antigravity-cli/adapter.ts` layers a scoped environment on `baseScopedEnv()` so proxy and third-party vendor variables cannot redirect traffic or loop back into OpenCodex. On Windows production turns (when `~/.gemini/jetski-standalone-oauth-token` is absent), `stageAntigravityWorkspace` supplies an empty temporary `HOME`/`USERPROFILE` (`ocx-antigravity-home-*`) while `agy` continues reading credentials from Windows Credential Manager, physically isolating the turn from host global `~/.gemini` `user_rules`, skills, and MCP servers.

Each cold turn or warm-session spawn creates an exclusive `mkdtemp` workspace (`0700`) and writes files with `flag: "wx"` (`0600`):
- `.agents/agents/ocx_bridge/agent.md` invoked via `--agent ocx_bridge`, setting `mainAgent: true`, `subagent: false`, `model: inherit`, `inheritCustomizations: true`, `inheritMcp: false`, and `tools: []` (or `["view_file"]` when inline base64 images are staged; `view_file` resolves to `read_file` internally, so declaring `["view_file", "read_file"]` together fails `agy` startup with exit code 3 `tool name conflict: multiple tools resolved with name "read_file"`). `inheritCustomizations: true` is mandatory because `inheritCustomizations: false` disables project `.agents/hooks.json` `PreToolUse` execution (`hook_called_count = 0`), and `settings.json` `permissions.deny` alone cannot block out-of-workspace reads or `StartLine`/`EndLine` arguments when `read_file(.ocx-images/*)` is enabled. Its Markdown body replaces `agy`'s built-in IDE system prompt with the caller's system/developer instructions (sanitizing Anthropic billing headers, Claude Code / Claude Agent SDK subagent identity declarations (#2899), Codex / inherited subagent identities (#5217), OpenCode CLI preambles, `ocx-claude-*` aliases, and proxy routing comments), explicit rules ignoring inherited external customizations and forbidding plain-text replay markers (`USER:`, `ASSISTANT:`, `TOOL RESULT`, `[Tool call: ...]`), optional structured-output instructions, and exact MCP tool aliases without exposing prompt text in `argv`. When caller tools are present, `mcpServers` in `agent.md` frontmatter registers the shared capture-only `src/adapters/codebuddy/mcp-server.ts` (`catalog.json` + `captured-calls.jsonl`, plus `tool-results.jsonl` on warm sessions) under `ocx_turn_bridge` with `eager: true`.
- `settings.json` conforming to `https://antigravity.google/schemas/v1/settings.json`, setting `trustedWorkspaces: [turnDir]`, `toolPermission: "request-review"`, `historySize: 0`, `allowNonWorkspaceAccess: false`, `disableSlashCommands: true`, and `permissions.deny` across `command(*)`, `write_file(*)`, `read_url(*)`, `execute_url(*)`, and `read_file(*)` (narrowed to `read_file(.ocx-images/*)` allow + explicit staged config/capture file deny when images are staged), plus `mcp(*)` when no client tools are declared.
- `.agents/hooks.json` + `allowed-tools.json` wiring `ocx-pretool-guard` (`src/adapters/antigravity-cli/pretool-guard.ts`, or `__antigravity-hook` in standalone binaries) on `PreToolUse` (`matcher: "*"`). The guard enforces `MAX_HOOK_STDIN_BYTES = 33_554_432` (`32 MiB`, `Math.max(32 MiB, projectedHistoryCharLimit(ANTIGRAVITY_CLI_CONTEXT_WINDOW) * 4)`) and fails closed (`decision: "deny"`) on byte-ceiling overflow, malformed payloads, or internal errors. Only `mcp_ocx_turn_bridge_*` tools and `view_file`/`read_file` calls targeting exact staged `.ocx-images/*` paths (via `Path` or `AbsolutePath`, without `StartLine`, `EndLine`, or `ContentOffset`) are permitted.
- On single-shot completion or warm-session eviction/TTL expiry/shutdown (including synchronous process-exit shutdown via `disposeAllSync`, which reaps live `agy` trees with `taskkill /T /F` on Windows and retries `EBUSY`/`EPERM` removals), `turnDir`, any owned temporary `HOME`, and `agy`'s `~/.gemini/antigravity-cli/brain/<conversation_id>` transcript directory are removed so proxied turns leave no session state on disk. Emitted adapter errors and non-zero exit `stderr` tails are redacted (`redactAntigravityLogText` / `redactSecrets`) and UTF-8 capped at `2,048` bytes in `service.log` (with the last 5 frame summaries logged on empty completions).

## Models, multimodal images, and client tool ownership

`src/adapters/antigravity-cli/profiles.ts` publishes only three collapsed Gemini 4 base models (`1,048,576` context window, `65,536` max output tokens, `["text", "image"]` input modalities):
- `gemini-4-carbon`: efforts `low`, `medium` (default), `high` -> `--model gemini-4-carbon-{low,medium,high}`.
- `gemini-4-argon`: efforts `low`, `medium` (default), `high` -> `--model gemini-4-argon-{low,medium,high}`.
- `gemini-4-hydrogen`: efforts `low`, `medium`, `high` (default), `xhigh` -> `--model gemini-4-hydrogen-{low,medium,high,xhigh}`.

Inline `data:image/(png|jpeg|jpg|gif|webp|bmp|tiff);base64,...` parts in `user` and `toolResult` messages are enforced at `16` images / `32 MiB` on the active turn and staged across a truncation-aware sliding window of up to the newest `16` surviving images / `32 MiB` into `turnDir/.ocx-images/`, preserving turn-stable relative markers in historical blocks while listing workspace paths at the tail for `view_file`; as long as any historical image remains inside that 16-image sliding window, subsequent turns stay on the single-shot isolated path. Developer/system instruction images, file-backed image IDs, remote image URLs, and video fail closed with HTTP 400 before spawning `agy`.

Staged `agent.md` system prompts pass unclipped through `600 KB`, whereas `agy` truncates a single `stdin` user frame around `191.5 KB` (`185 KB` passes; `210 KB` clips the tail). Cold-start replay in `src/adapters/antigravity-cli/protocol.ts` therefore caps history at `ANTIGRAVITY_COLD_HISTORY_CHAR_LIMIT = 180_000` characters from the head at whole-message checkpoints (protecting the active turn at the tail), omits assistant `thinking` blocks (`omitThinking: true`), and joins message blocks with `\n\n` so replay labels never concatenate. Warm-session continuation (`pool.acquireContinuation`) runs before cold truncation so multi-turn sessions (`>300 KB`) continue incrementally and hit Gemini prefix caching (`cache_read_tokens > 0`) across Carbon, Argon, and Hydrogen. Because `agy` reports `input_tokens` disjoint from `cache_read_tokens` (`total_tokens = input_tokens + output_tokens` with `thinking_tokens` inside `output_tokens`) and accumulates `result.usage` across warm turns, `subtractRawAntigravityUsage` (against `session.usageBaseline`) and `usageFromAntigravityRecord` restore per-turn cache-inclusive `OcxUsage.inputTokens` so `/v1/messages` and telemetry aggregation preserve uncached input without double-counting `cacheRead`. `buildAntigravityCliToolBridge` sanitizes tool schemas for Cloud Code Assist (`src/adapters/google-tool-schema.ts`) under `ANTIGRAVITY_TOOL_LIMITS` (`src/adapters/codebuddy/tool-bridge.ts`: `maxTools = 512`, `4 MiB` catalog ceiling, `maxTurnToolCalls = 16`). During streaming, `protocol.ts` strips echoed leading `ASSISTANT:` prefixes without buffering full responses, intercepts forged `[Tool call: ...]` text markers when `capturedToolCalls === 0` as `AntigravityTerminalRefusalProtocolError` (`terminalRefusal: true`, mapped to terminal `response.failed` on `/v1/responses` alongside `tool_catalog_invalid`, `tool_call_limit`, `undeclared_tool_call`, `tool_bridge_init_mismatch`, hook byte-ceiling denials, and upstream `INVALID_ARGUMENT`), releases pending bridged calls if the same `step_index` transitions to `state: "ERROR"` so the model can self-correct or answer in text, and coalesces parallel `mcp_ocx_turn_bridge_<alias>` calls over an `80ms` quiet window (`DEFAULT_TOOL_BATCH_COALESCE_MS`) using untruncated arguments from `captured-calls.jsonl`. While `DEFAULT_TOOL_BATCH_COALESCE_MS` and `maxTurnToolCalls = 16` bound concurrent MCP bursts, live `agy 1.5.9` dispatches isolated MCP `CallTool` requests serially one at a time, so multi-tool plans surface one bridged call per HTTP turn and resume on warm continuation with `0` extra LLM re-prompt tokens.
