# Mandatory Translated Chat Tool Results

`src/adapters/openai-chat/required-tool-result.ts` requires a completed client tool call before a clean terminal for required, named or required allowed-tool choices. Text and reasoning do not satisfy it. The existing response bridge owns selected-name authorization and alias restoration, so valid namespace/code-mode echoes keep their existing interpretation. Missing required calls become a non-retryable `required_tool_not_called` error with upstream usage preserved. Earlier output stays delivered and the guard neither buffers a stream nor sends another request. Existing errors and truncated outcomes retain their classification; auto/none remain unchanged. Sidecar-bearing catalogs bypass this client-call guard because their execution owner governs completion. Native passthrough and other adapters retain their existing contracts. When the failure ends a stream that produced no output, combo stream preflight (`src/server/responses/combo-stream-preflight.ts`) treats a `response.failed` carrying `required_tool_not_called` as final, so the combo does not send the same turn to another target.

The guard forwards the per-exchange stream context unchanged, preserving the opt-in [completed tool blocks](completed-tool-blocks.md) contract while counting early closed calls toward the same required-tool guarantee.
