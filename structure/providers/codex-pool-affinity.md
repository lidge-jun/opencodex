# Durable Codex Pool Affinity

This doc owns how Codex pool session pins and conversation-state issuers survive a proxy restart.
`src/codex/routing/thread-affinity.ts` keeps the live maps and calls the store at every bind, delete, clear and lookup.
The conversation key, cohort anchors and lineage are owned by [OpenAI Provider Account Modes](openai-tiers.md);
the single-writer lease is owned by [Responses spend](../transports/responses-spend.md).

`src/codex/routing/thread-affinity-store.ts` restores eligible pool bindings after a graceful proxy restart for up to 24 hours idle. Session-bearing requests and session-less requests anchored on their immediate parent have derivable anchors. Deeper session-less chains, keys derived under another config home, legacy raw-parent keys and evicted anchors remain memory-only. Removed, re-logged, expired or identity-less accounts are not restored; normal selection and usability rules still apply.

The config home contains `codex-affinity.sqlite`, mode 0600 with a hardened Windows ACL. Its v1 schema has `meta` (store secret and clean flag), `threads` (scoped bindings), and `issuers` (conversation state issuers). Row keys are domain-separated HMACs of the cohort anchor under the store's own secret; raw identifiers and process-local conversation keys are not stored. The identity fence derives from `quotaHistoryIdentity`, captured at bind and at issuance. Issuance requires both generation and `chatgptAccountId` to match the current record. `__main__` pins and issuers are never persisted. An unknown restored issuer scrubs continuation state; uploaded files are refused when the stored account differs from the serving account, as for known account changes and prior-account moves.

The spend-ledger lease is the single-writer authority. The final releasing hook flushes pending work and marks the store clean before ownership is released; it does so even when the release happens inside a passive read, because it commits only work recorded outside one. A crash, failed final flush or poisoned store leaves the clean flag unset, so the next owner discards rows. Structural changes use an ordered write log; UPDATE-only touches read live timestamps at flush, avoiding stale timestamps and resurrection. The 24-hour idle limit bounds reuse. Expired rows are removed by the next prune that commits: one is attempted when the store opens at lease acquisition, on an hourly timer while it stays open, and after every failed flush, including in a poisoned store. A prune can still be delayed or fail: a lease acquired inside a passive read does not open the store, a store that failed to open is disabled and cannot prune, a prune transaction can roll back, and timers can run late. SQLite secure_delete overwrites freed pages in the database file, but not filesystem snapshots, backups or storage remapping; its transient rollback journal is removed after each commit. The store secret pseudonymizes row keys and does not protect integrity from a local process that can already read the config directory. Pruning also removes future-dated rows and bounds each table to 2,048 entries, evicting model detours first. Other passive reads do not open, adopt or mutate the store. A new lease scope clears live affinity before restoring from the database.

`src/lib/config-ownership.ts` includes the database and sidecars in `INITIAL_OWNED_PATHS`; existing homes use `recordOwnedConfigPath`, whose ownership race is tracked in [#8093](https://github.com/lidge-jun/opencodex/issues/8093). `tests/codex-integration/codex-affinity-store.test.ts` and `tests/codex-integration/codex-affinity-restart.test.ts` cover store and restart behavior.
