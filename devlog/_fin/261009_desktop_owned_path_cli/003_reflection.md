## Dispositions of the material gaps

- **AM-5 One shared record contract, and disabled wins.** Both readers (Rust `cli_command_record.rs` and `src/lib/desktop-cli-record.mjs`) accept exactly the same validity rules for the fields 020 consumes: `version` 1; `enabled` boolean; when enabled, `bundle.platform` ∈ {`darwin`, `win32`, `linux`} equal to the host, `bundle.kind` the matching one of {`macos-app`, `windows-install`, `linux-deb`}, `bundle.cliExecutable` absolute with no `.`/`..` segment, no NUL or newline, at most 4096 characters. A shared fixture directory `tests/fixtures/desktop-cli-record/` (`valid-darwin.json`, `valid-win32.json`, `valid-linux.json`, `disabled-tombstone.json`, `pending-enabled.json`, `disabled-with-pending.json`, `appimage-kind.json`, `relative-target.json`, `dotdot-target.json`) is read by the TS reader tests and, through `include_str!`, by the Rust tests, so the two cannot drift. Precedence for handoff: `enabled:false` wins over `pending` (no target, package path continues); enabled + pending is an error (AM-2 text). Diagnostics still report `cleanup-pending` when a disabled record carries a pending journal, so unfinished cleanup is never hidden.
- **AM-6 External journal protocol** (completes AM-1). Each change has one journal file `~/.opencodex-desktop/journal/<generation>-<index>.json` (0600): `{"version":1,"kind":"file"|"registry-sz"|"registry-expand","path":string,"mode":number|null,"before":string|null,"after":string|null}`, bytes base64 for files and the raw UTF-16LE string base64 for registry values, `null` meaning absent. Limit 8 MiB per journal file; larger targets are refused (`rc-too-large`). The record's `pending.changes[]` holds `kind`, `path`, `journalFile`, `beforeSha256`, `afterSha256` (`"absent"` for a missing file). Order: write and fsync all journal files and the journal directory; write the record with `pending` and fsync; apply each change (temp file + fsync + rename, or registry set); write the final record with `pending: null` and fsync; then delete the journal files. Recovery at launch, under the lock: for each change, current digest = `afterSha256` → done; = `beforeSha256` → re-apply when the pending operation is still wanted (enabled for install, disabled for remove), otherwise leave; anything else → stop with `journal-conflict`, keep the journal and backups, report in status. Journal files whose digest does not match the record are ignored and reported.
- **AM-7 Ownership is tracked separately from current targets.** The record's `posix.rcFiles` is the list of files Desktop owns a block in, whatever the current environment says. Validation accepts any absolute recorded path there (with the same NUL/newline/length rules) instead of re-checking it against today's `ZDOTDIR`/`XDG_CONFIG_HOME`/bash login choice. On reconcile, Desktop computes the desired targets from the current environment, installs or repositions blocks there, and removes its block from any recorded file that is no longer desired, when that block's digest still matches. A recorded file whose block was edited by the user is left alone and reported (`owned-block-modified`). Remove walks the recorded list, not the current targets.
- **AM-8 ENOENT is re-checked.** After `spawn` fails with ENOENT, the launcher `lstat`s the recorded target. Only a second ENOENT (the file is really gone) resumes the package path; if the file exists, the launcher prints a fixed error and exits 127. Test: a target that is a script with a missing interpreter.
- **AM-9 A11 is verified on the compiled CLI, and unverified platforms are named.** 030 adds a compiled provenance check on macOS: build the host standalone CLI with `bun scripts/build-standalone.ts`, render the POSIX shim for it (Rust test helper that writes the shim for a given target path), and run `ocx claude` through the shim with a fake `claude` executable first on PATH that prints which `ANTHROPIC_*` names it received, in an isolated `HOME`/`OPENCODEX_HOME`, a shell-exported `ANTHROPIC_MODEL`, and a cwd `.env` setting `ANTHROPIC_BASE_URL`. Expected: the exported name survives and the `.env`-only name is stripped. If `ocx claude` cannot run in that isolated setup, no hidden test hook is added to the product to make it observable; the result is recorded as unverified, A11 is reported as residual in the PR, and the security review decides whether PR 1 may merge without it. Fish, Linux deb and Windows native terminal selection stay unverified by this unit and are listed as release QA items in both PR descriptions.
- **AM-2 corrected.** The launcher error for an invalid, unreadable, too-large or enabled-pending record says: OpenCodex Desktop's terminal-command record at <path> could not be used (<issue>); open OpenCodex Desktop to repair it, or run with `OCX_NO_DESKTOP_HANDOFF=1`. The sentence claiming that deleting the record is safe is removed: deleting it leaves the shim and rc blocks in place and loses ownership.

Minor gaps (field-name and limit syncing after AM-1, the AM-3 link diff and its surface assertion, AM-4 wording) are handled during implementation and checked in C.

## A audit round 1 (independent auditor `01a11f6b-c45b-70b1-8a39-9bbcd957970d`): FAIL, four blockers

Main dispositions, overriding everything above where they conflict:

- **AM-10 The first saved record already carries its bundle.** Blocker: `Record::fresh()` was `enabled:true` with `bundle:None`, and the first `transact()` saved it before any write, which AM-5's rule (enabled ⇒ valid bundle) rejects. Amended: reconcile computes `stable_bundle()` first; when there is no stable bundle (debug build, translocated, DMG, AppImage, unknown layout) nothing is written and only status reports the reason. A fresh record is built as `Record::fresh(bundle)` with the validated bundle, so every saved record, pending or settled, satisfies AM-5. A disabled tombstone (`enabled:false`) may omit the bundle. Test `fresh_stable_bundle_installs_without_npm` drives the real `fresh → transact → save → recover` path, and the shared fixtures include the first pending record shape.
- **AM-11 A lasting entry on every platform: the dashboard.** Blocker: the AM-3 bootstrap link disappears once the dashboard loads, and a Linux session without a tray has no other way in. Amended: AM-3 is withdrawn. The dashboard gets a desktop-only "Terminal command" entry next to its existing "Desktop update" entry, built the same way: `gui/src/lib/desktop-shell.ts` adds `desktopCliPageUrl()` / `openDesktopCliPage()` beside `desktopUpdatePageUrl()` / `openDesktopUpdatePage()` (`tauri://localhost/cli.html`, `http://tauri.localhost/cli.html` on Windows), and the entry renders only when `isDesktopShell()` is true. The tray item stays. Tests: GUI unit test of the URL helper per OS; the surface test asserts the entry is gated by `isDesktopShell`. The PR touching `gui/` carries a screenshot (AGENTS.md).
- **AM-12 Back uses the existing return path.** Blocker: `show_dashboard` goes through `navigate_once`, which refuses after the first dashboard load. Amended: `cli.js` calls the existing `return_to_dashboard` command, whose page guard is widened from "update page" to "update page or terminal-command page" (a `require_local_settings_page` that accepts exactly `/update.html` and `/cli.html` on the app origin and the `main` label). Tests: Rust URL-guard test covering both pages and rejecting others; surface test asserting `cli.js` invokes `return_to_dashboard` and never `show_dashboard`.
- **AM-13 The A11 check must be able to fail.** Blocker: `ANTHROPIC_MODEL` is not a protected slot, so its survival proves nothing. Amended check (030, macOS, compiled host CLI): isolated `HOME`/`OPENCODEX_HOME` configured for the native Claude route, a fake `claude` first on PATH that prints which protected names it received, a shell-exported `ANTHROPIC_AUTH_TOKEN` (dummy value), and a cwd `.env` setting `ANTHROPIC_BASE_URL`. Run 1 through the shim: `ANTHROPIC_AUTH_TOKEN` present, `ANTHROPIC_BASE_URL` from `.env` absent. Run 2, control, the compiled CLI directly without the shim: `ANTHROPIC_AUTH_TOKEN` absent. A11 counts as verified only when both runs match. Values are never printed, only names.
