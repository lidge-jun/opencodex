## Review blockers and correction

Maintainer `Ingwannu` requested changes on head `345e952…`: no contextual desktop notification, newest-observer-only dispatch, sync config I/O from response-header observation; also routing and persistence retry proofs. The later hold comment requests exact-head CI and full state-transition tests. Issue [#5649](https://github.com/lidge-jun/opencodex/issues/5649) specifies selected 5-hour/weekly windows, account/window/percent/reset context, manual pause until resume, and a policy separate from proactive switching.

1. **Alert surface.** Today `src/quota/reset-sinks.ts:1-14,38-79` has webhook/local-command delivery for *reset* events, and `src/server/management/quota-reset-routes.ts:20-56` exposes their recent history. Windows tray balloons exist in `src/tray/windows-tray.ps1:143,498-501`, but the proxy has no cross-platform OS-notification bridge for this threshold event. Add a bounded process-local low-quota alert ledger and authenticated read-only `GET /api/codex-auth/low-quota-events` (window, used percentage, known reset time, account id, timestamp, delivery/status). Keep the fallback log identifier-free and concise; authorized management readers may see the account id, as existing account routes do (`structure/gui-and-management-api.md:268`). `notify` means this observable backend alert in this slice; document that it does **not** create a desktop popup, and leave #5649 open for the desktop bridge. Do not reuse `/api/quota-resets` or silently claim a reset notification. Mark an episode delivered only after ledger publication; if an injected sink rejects, clear its in-flight marker for a later observation and record a bounded failure state.
2. **Multiple servers.** Change the observer slot from newest-only to fan-out to every live registration, with per-callback failure isolation and idempotent unregister. Each callback operates only on accounts present in its own live config and holds its own episode/pause state. Use the existing per-server background lifecycle lease (`src/server/background-lifecycle.ts:161-220`) to own registration and release, so a later or disabled server cannot suppress the earlier enabled one. Test two distinct configs/accounts, reversed stop order, and one throwing observer. Since the quota store itself is process-global by account id, test matching account ids under two configs as a deliberate global-observation case and verify each policy remains independent.
3. **Persistence latency/durability.** On threshold crossing, call `setCodexAccountPaused` in memory before the next selection, then enqueue one coalesced, bounded, failure-isolated config save per server after the current observation turn; no config filesystem call in `observeCodexLowQuota`. A deferred writer owns retries with a bounded delay and terminal warning/alert status; a second high observation may also request a retry. Flush/await pending save during normal shutdown, and report save failure rather than claiming a durable pause. This retains the existing atomic/rebased save at `src/config/live-reconcile.ts:425-440` without changing its lock semantics. A restart before a successful save cannot promise preservation; document that limit.
4. **Policy edges.** Enabled policy must select at least one action and one window. Restrict threshold to 1–100 used percent (zero would fire on measured zero); disabled/omitted policy stays valid. A manual resume suppresses immediate repause within the same account/window episode; re-arm only after a below-threshold reading or a new reset episode. No automatic resume at reset. Distinguish notification success, in-flight, and failure; keep pause idempotent. No eligible account must produce the existing explicit failure, never borrow the paused account. Preserve the main hard lock without altering its threshold or evidence rules.
