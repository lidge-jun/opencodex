## 판정 1: 가격 변경 — 채택하지 않음

PR 주장: "$0.30/$1.20이 stale, $0.60/$2.40/$0.12로 갱신."

MiniMax 공식 pay-as-you-go 가격 기준 실제 구조:

| 입력 구간 | 정가 | 상시 50% 할인가 | 캐시 읽기 |
|-----------|------|----------------|----------|
| ≤512K | $0.60 / $2.40 | **$0.30 / $1.20** | $0.06 |
| >512K | — | $0.60 / $2.40 | $0.12 |

즉 PR이 넣으려는 숫자는 **>512K 구간 가격 = ≤512K 정가**이고, 현재 카탈로그 값은
**실제 과금되는 상시 할인가**다. 둘 다 공식 숫자이며 stale 여부의 문제가 아니라
**어느 기준을 단일 값으로 쓸지의 정책 결정**이다.

추가로, 우리 minimax M3 행의 `contextWindow`가 `1000000`이라 두 구간이 한 행에
섞여 있다. 정가로 바꾸면 실제 청구액 대부분을 2배로 과대표시한다. 사용량/비용 회계
(`tests/usage-cost.test.ts` 경로)에 직접 영향을 준다.

→ **가격은 이 라운드에서 건드리지 않는다.** 정책 결정이 필요하면 별도 이슈.

## 판정 2: video 입력 — 채택

> **재감사 후 정정 (라운드 2, NEW-3)**: 초판(및 개정 1판)은 "우리 minimax 프리셋이
> `anthropic-messages` + `https://api.minimax.io/anthropic`이라 문서와 같은 경로"라고
> 썼다. **틀렸다.** 우리 레지스트리는 `openai-chat` + `/v1`이다:
>
> ```
> src/providers/registry.ts:1001  minimax     adapter: "openai-chat", baseUrl: "https://api.minimax.io/v1"
> src/providers/registry.ts:1013  minimax-cn  adapter: "openai-chat", baseUrl: "https://api.minimaxi.com/v1"
> ```
>
> `rg "api.minimax.io/anthropic" src/`는 생성 파일 밖에서 아무것도 반환하지 않는다.
> `anthropic-messages` + `/anthropic`은 **jawcode 소스 행의 메타데이터**이지 우리
> 프리셋이 호출하는 경로가 아니다. 근거와 코드 경로가 어긋나 있었다.

결론은 유지되지만 근거를 올바른 경로로 교체한다. MiniMax는 **OpenAI 호환 경로에서도**
video 입력을 문서화한다:

- `POST https://api.minimax.io/v1/chat/completions`에 `video_url` 콘텐츠 파트
- 포맷 MP4 / AVI / MOV / MKV
- 크기: 직접 전송 50MB, Files API 경유 `mm_file://{file_id}`로 512MB
- `fps` 0.2–5 (기본 1)

출처(우리 경로에 해당): <https://platform.minimax.io/docs/api-reference/text-openai-api>,
파일 업로드 <https://platform.minimax.io/docs/api-reference/file-management-upload>.

Anthropic 호환 경로는 블록 형태가 다르다(`{"type":"video","source":{...}}`,
`video_url`이 아니다) — 우리가 쓰지 않는 경로이므로 참고만 한다
(<https://platform.minimax.io/docs/api-reference/text-chat-anthropic>). 두 경로 모두
**M3 전용**이라는 구분은 동일하게 유지되어 M2 계열을 건드리지 않는 경계를 뒷받침한다.

→ 우리 `openai-chat` 프리셋에 대해 `text,image` → `text,image,video` 교정은 옳다.

### 다만: 와이어 구현은 없다 (정직한 한계)

`rg "video_url|input_video" src --glob '!src/generated/**'` → **결과 없음**.
즉 `src/`의 어떤 코드도 `video_url` 파트를 만들지 않는다. 요청 빌더도, 비전 사이드카도
비디오 경로가 없다.

따라서 이 교정이 하는 일은 **카탈로그가 video를 광고하는 것**이며 = Codex 앱이
`minimax/MiniMax-M3`와 `minimax-cn/MiniMax-M3`에 대해 비디오 첨부를 **받아들이게** 된다.
실제 전송 경로는 없다. 이 간극을 숨기지 않고 후속 작업으로 분리해 기록한다
(`video_url` 파트 생성은 이번 라운드 범위 밖).

## 재생성 차단 근거 (블로커 1, 실측)

감사자가 `src/` + `scripts/`를 임시 디렉터리에 복사하고 `node_modules`를 심링크한 뒤
현재 jawcode `models.json`에 대해 제너레이터를 돌렸다. 커밋된 생성물과의 델타:

| 항목 | 개수 |
|------|------|
| 필드가 바뀐 모델 | 95 |
| 가격(cost) 변경 | 63 |
| 신규 추가 모델 | 36 |
| 삭제 모델 | 0 |
| 입력 모달리티 변경 | 0 |

메인 세션도 독립적으로 재현했다(확인 직후 `git checkout HEAD --`로 원상복구):
번들 7개가 변경 — `amazon-bedrock`, `anthropic`, `cerebras`, `google`, `opencode-go`,
`openrouter`, `xai` — 그리고 `PROVIDER_ALIASES` 순서까지 재정렬된다
(`"zhipu-bigmodel"`이 마지막 → 31번째 위치).

```

**즉 커밋된 생성물은 이미 상위 소스와 어긋나 있다.** 원인은 동기화를 강제하는 테스트가

`codex-catalog`, `slug-codec`만 반환하고 그 어느 것도 재생성 후 비교를 하지 않는다.

따라서 초판의 수용 기준 "생성물 diff에 가격 변경 0건"은 **달성 불가능**했고, 같은
문서의 "무관한 행이 바뀌면 D 요약에 기록한다"는 완화 문장과 정면으로 모순됐다.
그대로 진행하면 "가격은 건드리지 않는다"고 선언한 work-phase가 조용히 가격 63건을
비용 회계에 밀어넣는다.

### 손으로 생성물을 고치는 우회를 쓰지 않는 이유

재동기화를 먼저 하면 video는 한 행 델타로 깨끗하게 떨어지므로 **순서가 진짜 의존성**이다.
→ wp5(090 문서)가 선행하고 생성물 반영은 거기서 닫는다.
