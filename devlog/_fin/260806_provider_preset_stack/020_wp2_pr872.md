## What the PR changes

### `src/providers/registry.ts`

Two module-level allowlists are added above the registry array (near
`BASETEN_MODEL_INPUT_MODALITIES`):

- `DIGITALOCEAN_CHAT_COMPLETION_MODELS` — 26 ids, `as const`
- `SCALEWAY_SERVERLESS_CHAT_MODELS` — 10 ids, `as const`
- `SCALEWAY_MODEL_INPUT_MODALITIES` — `pixtral-12b-2409: ["text","image"]`

Then two registry entries after `commandcode`:

- `digitalocean` — `https://inference.do-ai.run/v1`, `openai-chat`, key auth,
  `liveModels`, `preserveCustomDestination`, `parallelToolCalls: false`,
  `reasoningEfforts: []`, discovery bounded 256 KiB / 256 rows with
  `filter.allOf[{ path:["id"], equalsAny: DIGITALOCEAN_CHAT_COMPLETION_MODELS }]`.
- `scaleway` — `https://api.scaleway.ai/v1`, same shape, `freeTier: true`,
  `modelInputModalities: SCALEWAY_MODEL_INPUT_MODALITIES`, bounded 128 KiB /
  128 rows, filtered against `SCALEWAY_SERVERLESS_CHAT_MODELS`.

The design difference from WP1 is the **fail-closed allowlist**: both providers'
`/v1/models` rows carry only `id/object/created/owned_by`, with no modality
discriminator, so a live row must ALSO appear in the registry-owned list. A
newly published model stays hidden until a docs-backed registry refresh. That is
the conservative direction and should be preserved through the rebase.

One decision worth keeping visible in review: `gpt-oss-120b` is deliberately
omitted from the Scaleway list because Scaleway requires the Responses API for
its tool calling while this preset routes agent tools through Chat Completions.
That comment must survive the rebase — it is the reason a user will not find the
model.

### `src/providers/free-directory.ts`

row because the service requires a prepaid balance — correctly, the preset does
