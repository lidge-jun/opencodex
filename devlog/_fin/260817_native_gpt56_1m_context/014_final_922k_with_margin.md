# 014 — 최종 결정: 922,000 (970,000 안 철회)

013은 `context_window = 970,000`을 제안했다. 철회한다. 사용자 지적이 옳다.

## 970,000이 틀린 이유

013의 계산 자체는 맞다: `970,000 × 0.95 = 921,500`으로 측정 상한 922,000 바로 아래에 붙는다.
문제는 그게 **목표가 되어서는 안 된다**는 점이다.

측정된 경계는 `921,160 성공 / 923,000 거절`이다. 921,500은 그 사이 1,840토큰 폭의
틈에 정확히 착지시키는 값이다. 즉 마진이 사실상 없다. 토크나이저 차이, 툴 정의 변화,
upstream의 미세 조정 하나에 바로 실패한다.

95%는 Codex가 이미 마련해 둔 안전 여유다. 그 여유를 "낭비"로 보고 정확히 상한까지
소진하도록 ctx를 역산하는 것은 안전장치를 무력화하는 것이다.

## upstream이 실제로 하는 방식

라이브 카탈로그를 다시 읽으면 계약이 분명하다:

| slug | context_window | max_context_window | 여유 |
| --- | --- | --- | --- |
| gpt-5.6-sol | 272,000 | 872,000 | 600,000 |
| gpt-5.4 | 272,000 | 1,000,000 | 728,000 |
| gpt-5.5 | 272,000 | 272,000 | 0 |
| gpt-5.3-codex-spark | 128,000 | 128,000 | 0 |

**`context_window`는 하드 상한이 아니라 운영 cap이다.** 5.6은 872k까지 갈 수 있는데도
272k로 운영한다. 372k도 같은 성격의 값이었다 — 지원 한계가 아니라 우리가 정한 cap.

여기서 배울 점: cap은 상한에서 여유를 두고 정한다. 상한에 맞춰 역산하지 않는다.

## 채택: 922,000

```
NATIVE_GPT56_CONTEXT_WINDOW    1_050_000 -> 922_000
NATIVE_GPT56_MAX_INPUT_TOKENS  922_000 (유지)
auto_compact_token_limit       min(floor(922000*0.9), 922000) = 829_800
```

| 지표 | 값 |
| --- | --- |
| Codex 실제 한도 (95%) | 875,900 |
| 화면 표시 | ~876k |
| 하드 상한(922,000)까지 마진 | 46,100 |
| auto-compact 발동 | 829,800 (한도보다 46,100 아래) |

세 겹이 된다: compaction 829,800 → Codex 한도 875,900 → 실측 상한 922,000.
각 단계마다 46k씩 여유가 있다.

## 세 안 비교 (최종)

| 안 | ctx | Codex 한도 | 상한까지 마진 | 판정 |
| --- | --- | --- | --- | --- |
| 배포된 현행 | 1,050,000 | 997,500 | **-75,500 (초과)** | 실패 유발 |
| 013안 | 970,000 | 921,500 | 500 | 마진 없음 |
| **채택** | **922,000** | **875,900** | **46,100** | 안전 |

## 나머지는 013 그대로

- `[1m]` 파급은 경로별로 다름 (main-session auto-context는 922k >= 350k라 계속 붙음).
- `NATIVE_CAP_OPTIONS`의 1,050,000 -> 922,000.
- Daybreak도 같은 상수라 함께 내려감.
- API 키/OpenRouter의 1,050,000, `NATIVE_GPT56_MAX_INPUT_TOKENS = 922,000` 유지.
- 갱신 대상 테스트 11개 파일은 013의 목록 그대로.

## 남는 질문 (사용자 판단 영역, 이번엔 미적용)

872k(라이브 `max_context_window`)를 넘어서는 값을 광고해도 되는가?
922,000은 upstream이 보고하는 872,000보다 크다. 실측으로는 921,160이 통과하므로
872,000은 하드 상한이 아니지만, upstream 보고값을 넘는 광고라는 점은 기록해 둔다.
더 보수적으로 가려면 872,000(→ 95% 후 828,400)이 선택지다.
