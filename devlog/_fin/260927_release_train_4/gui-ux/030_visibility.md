# Phase 030 — global and provider visibility assessment (#5617)

**Decision under audit:** reimplement the useful global/provider distinction on current `dev` after Phase 010, subject to the account-pool lane finishing the shared provider UI owner. The stale draft is 369 commits behind `dev` and conflicts in `app-routing.ts`, `Providers.tsx`, and `structure/config.md`; a mechanical carry could break the current JEV Auto deep link and provider CTA. If that owner is still changing or a stable config migration cannot be shown, defer with evidence.

Move new logic into siblings before the 2,792-line Models cap is reached. Preserve dense operator layout and keyboard operation.
- **MODIFY** `structure/catalog.md`, `structure/config.md`, `structure/gui-and-management-api.md` and matching `docs-site` model-routing/dashboard guides; **MODIFY** focused catalog/management/GUI tests and both test-layout inventories for any new files.

## Acceptance or deferral test

Prove: globally hide one exact model ID; add a new provider with that ID; it stays hidden in catalog while a direct route still works. Locally hide one provider's ID; another provider's same ID stays visible. Reload, sync and restart preserve these states. An empty provider list explains whether global hide or provider selection caused it. Open the existing JEV Auto CTA and `#models/combos/jev-auto` deep link after the new provider link is added; both must still resolve to the Combos action. Force a global visibility PUT to hang until its timeout, then verify the busy state releases and a late response cannot overwrite a newer switch state. Inspect before/after browser flows at desktop/400px and long locale. Run a dedicated management/security review and exact-head CI. If a stable migration from old `disabledModels` cannot be established, leave #5617 open with a detailed English comment rather than changing semantics mid-train.

## Rollback

If adopted, the new persisted global hide field needs an explicit rollback/migration before a UI revert. A revert must either translate it back into the existing visibility representation with a documented precedence or remove it only after the operator is shown the affected exact IDs; leaving invisible models behind an absent control is unacceptable.
