# Phase 050 — merge evidence and post-merge cleanup

Before each selected PR: fetch the latest `origin/dev` and contributor head; compare diff and merge-base; build the next lane branch from the **previous accepted dev merge SHA** (or current `origin/dev` for the first branch), then rebase that branch to the exact current `dev` tip and rerun tests affected by the rebase. Check the union of prior lane changes with the new diff. Prove the `Models.tsx` cap with `bun test tests/ci-workflows/file-size-ratchet.test.ts`; `scripts/test-layout/layout.json` is an inventory to keep synchronized with `tests/fixtures/test-layout-expected.json`, not a file-size-baseline entry. Review union/locale rosters. Write the PR template's Summary, Verification and Checklist with exact commands, results, full-suite contention exception, current screenshot `pr-assets` commit SHA URLs, and contributor `Co-authored-by` trailer. No screenshot files in the code branch.

Inspect GitHub required checks against the PR's current `headRefOid`; skipped, cancelled, pending and older-head results are not success. Resolve valid Codex/CodeRabbit findings; merge only after all required checks succeed and MAINTAINERS.md security/review rules are satisfied. Record each merge SHA, CI run URL, source PR close/comment and linked issue close/comment. Fetch `dev` after each merge and verify its current CI; repair any regression owned by this lane before the next batch. The final report names merged PRs, exact SHAs, held work, source credit, browser evidence and remaining risk.
