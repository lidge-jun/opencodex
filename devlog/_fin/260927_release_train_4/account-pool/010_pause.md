## New-field path and limit of enforcement

The proposed `ProviderAccount.paused` field has this complete chain: creation by the authenticated management pause route and CLI/GUI action into `setAccountPaused` (`src/server/management/oauth-account-routes.ts`, `src/cli/account-extended.ts`, `gui/src/hooks/useProviderAccountPools.ts`); serialization by `src/oauth/store.ts` through the existing atomic store writer and by the masked management DTO; deserialization by `normalizeAccount` in `src/oauth/store.ts` and the GUI provider-account type; consumption by active-survivor choice, `commitOAuthAccountSelection`, `src/oauth/index.ts` credential acquisition, `generic-account-failover.ts` preference/rotation, Guardian/catalog/image/Responses callers, and the Providers card. Unknown/malformed persisted values normalize to unpaused; no migration version is added because the optional field is backward compatible. The new `KiroSkipReason.paused` value is created by `kiroAutoSelection`, sent through the existing status/GUI path, and rendered by `gui/src/kiro-device-login-helpers.ts` and locale strings; it is not separately persisted (N/A: derived diagnostic).

The pause boundary is product runtime code, so the Codexclaw E1–E8 process-tier taxonomy is not itself an enforcement layer for an installed proxy. Executing surfaces are store mutation, selector and credential acquisition. Known bypasses are direct upstream requests outside the proxy and an already admitted request whose credential was captured before the pause commit; a local process with the user's own credential files can also change them. Residual risk is that pause cannot revoke an in-flight provider send. Wording is therefore “excludes new automatic selections after the committed mutation,” not a claim of instantaneous revocation or hostile-process containment. Final layer for those bypasses: none inside this proxy; the negative tests assert the narrower admission boundary.
