# 070 Release 2.14.2

The goal's DONE criteria end with "the release completed". That is the one clause still
open: `package.json` says 2.13.0, the newest tag is `v2.14.1`, and **68 commits sit on
`origin/main` since that tag** — including the nine that fix this incident.

## Version

`2.14.2`. The shipped change is a defect fix on an existing surface: no new API, no
behaviour a caller opts into, and `/api/usage` responses are byte-identical to a cold read
in every truncation state (032). Patch is the honest level. `v2.14.2` is unused, so the
NEEDS_HUMAN collision clause does not apply.

## Note on package.json

It reads 2.13.0 while the newest tag is v2.14.1, because the release workflow bumps the
manifest in its own commit and `main` here has moved on since. `scripts/release.ts` takes
the target version as an argument and writes it, so the stale manifest is an input to the
release rather than something to hand-edit first.

## Procedure

`bun scripts/release.ts 2.14.2 --tag latest --publish`, which runs its own preflight
(clean tree, dependency audit, typecheck, tests, privacy scan), bumps and commits the
version, pushes, waits for Cross-platform CI, then dispatches and watches the Release
workflow. Publishing is tokenless via Trusted Publishing (OIDC); there is no NPM_TOKEN to
supply.

The script is the release authority per AGENTS.md. Do not hand-roll `npm publish`, and do
not weaken its gates — a local full-suite hang is a local problem, not a reason to skip the
preflight the script runs in CI.

## Acceptance

- `v2.14.2` tagged on the promoted `main` commit.
- Release workflow green.
- `npm view opencodex version` returns 2.14.2.

## Risk

The user authorized push, preview/main promotion and deploy for this work. Release is the
last authorized step of that same instruction ("main preview 머지하고 배포해 반드시"), not
an expansion of it. If CI or OIDC is unavailable, that is the goal's BLOCKED clause and the
phase stops there rather than publishing by hand.
