## wp3 executable refinement after source consultation

The following decisions supersede broader or ambiguous wording above. Consume the previous D and source baseline in 031. Same-architect proposal `.tmp/cli-parity/wp3-architect.md` and the separate scratch security consultation informed these choices; final reflection/A are required before B.

**CP-ARCH-03 / editor authority.** The lazy batch owner imports the existing named `parseProviderEditorConfigDTO` from `src/server/auth-cors.ts`; no field-policy copy or authentication-module extraction. Snapshot requires valid config/provider records, selects exactly defaultProvider/providers, removes only hasApiKey/hasHeaders/xaiResponsesOptInState/initialModelSelection from fetched rows, then validates through that parser before any output. Unexpected secret/unknown fields fail closed. User baseline/next documents are parsed as-is: no derived-field stripping, normalization, default seeding, URL re-redaction or repair. CLI diagnostics expose fixed shape/classification, never the parser's interpolated field/provider text. The existing server validates nested values, dependencies, DNS and CAS, preserving unchanged private data under the public baseline.

**CP-UX-01 / input interface.** `readJsonInput(pathOrDash: string, deps: RuntimeApiDeps = {}, label = "JSON input"): Promise<unknown>` and `serializeManagementJson(value: unknown): string` are the only new generic exports from json-input.ts. Reuse the server-owned MANAGEMENT_JSON_BODY_MAX_BYTES (4 MiB), not a second limit. Explicit '-' reads bounded stdin via readSecretBytes; default total input deadline is 30 seconds, tests use stdinTimeoutMs. Check TTY before reading. File reads accept regular files only, enforce the running byte cap and deadline, close owned handles/readers on every path and refuse special files without blocking on FIFO open. Strict UTF-8 accepts one normal leading BOM; valid arrays remain valid generic JSON for later consumers. Wipe mutable input buffers in finally; no claim of immutable-string erasure. Never echo raw I/O/decoder/JSON errors, path values, payloads or causes. Batch rejects two '-' sources, duplicate/conflicting options and missing values before reading. Serialize the validated exact `{baseline,next}` object once and check its composite UTF-8 size before HTTP; individual caps do not authorize a larger wire body.

**CP-UX-03 / fixed-target transport.** Each new multi-request operation resolves runtimeBaseUrl once after argument/input validation and passes the pinned baseUrl to every runtimeRequest. Fixed methods/routes use `redirect:"error"`; input URLs remain provider body data, never management destinations. No JSON/argv management-origin override, local fallback, hidden retry or unrequested credential channel is added. Live add uses duplicate-aware takeOptionWithSyntax for credential-valued inputs and fixed/redacted leftover diagnostics. The no-force existence check uses the target roster; target presets supply auth/responsesPath and the canonical OpenAI provider seed. A missing target preset without sufficient explicit custom fields refuses rather than falling back to the local registry. An explicit --force permits the existing upsert; the preflight-to-POST race remains documented.

**CP-ARCH-03 / pacing semantics.** Read returns `{provider,rules,status}` from pinned GET /api/config and GET /api/provider-request-pacing?name=P. Absent configured block is rules:null; missing provider/malformed response is failure. Scalar edits use only the config block, preserve observed model rules and PATCH only requestPacing. Exact flags: --enabled on|off, --rpm number (finite fractional values permitted by canonical bounds), --min-interval-ms integer, --max-concurrent integer. Missing block starts disabled; numeric flags do not silently enable. --file FILE|- is exclusive with scalar flags, validates a complete non-null block and writes without a prior rule read. Reuse requestPacingConfigError for strict nested validation. Zero is invalid for pacing limits and provider contextWindow; it is not a clear operation. Scalar PATCH is whole-block replacement and can overwrite an intervening edit; use snapshot/apply when public-baseline CAS is required.

**CP-UX-03 / safe provider outcomes.** Main owns a small provider-result.ts shared by the three provider domains. Export `runProviderAction(action: () => Promise<number | void>): Promise<number>` and `printProviderReceipt(value: unknown, wantsJson: boolean, action: string): number`. It retains valid, allowlisted success/name/defaultProvider/droppedCustomModels/disabled/hasApiKey/xaiResponsesOptInState/dependentShadowIntercept/catalogRefresh data only; invalid/unexpected receipts refuse rather than dumping arbitrary fields. Boolean flags remain booleans; xAI opt-in is boolean or mixed; droppedCustomModels is a nonnegative safe integer; dependentShadowIntercept is only {model:string,enabled:boolean}, with terminal-safe human rendering. CatalogDisposition's committed/skipped/failed and closed reason/cause vocabulary are retained. A persisted response with failed refresh or skipped busy/stale/refused/catalog-unavailable exits 1 and says saved but not converged; skipped not-requested/null/absent refresh does not imply a client sync and may exit 0. Never print arbitrary RuntimeApiError.body. Known provider error codes map to fixed messages; arbitrary nested code/message/details/issues/cause fields are not echoed. HTTP404 remains exit4,409 exit5,other failure1; static usage errors remain2. An unknown transport outcome is not reported as rollback or retried.

The originally proposed general nested-error change to runtime-api.ts is narrowed: provider-result owns the new provider error projection, using fixed known-code/status messages and retaining the typed HTTP status. Global existing command errors/output are untouched in this phase. This meets the security scalar-policy requirement without importing arbitrary nested server messages into every CLI path. Later routing work may separately justify its own message projection.

**CP-UX-03 / local sync correction.** Existing no-live provider add remains the local writer. New --responses-path and --auth-mode values join its domain parser with validation before save. Requested local --sync executes before JSON/human output using syncModelsToCodex's quiet logger. Preserve existing no-sync JSON fields and needsSync:true; add an explicit sync disposition only when requested. Applied client sync alone clears needsSync. Catalog-only, policy-skipped, no-proxy, refused and failed stay distinct; no-proxy/refused/failed return nonzero while stating the local save happened. Policy-skipped ok:true can return0 with needsSync:true. Human output must not say synced for stopped, thrown, catalog-only or skipped cases. Do not globally redesign runCliAction: each new domain returns its numeric exit and provider dispatch propagates it.

**Deletion/CAS scope.** Live remove --yes is one DELETE and retains server dependency/default/account cleanup rules. Batch removals/renames require --yes based on own baseline keys absent from next; PUT remains one exact body with no replacement-baseline fetch or retry. Batch does not claim DELETE's OAuth credential cleanup. Snapshot carries no cross-invocation target token; document applying on the intended host/context. Pinning is within one invocation and does not promise immunity to listener replacement.
