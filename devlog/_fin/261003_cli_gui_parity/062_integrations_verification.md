# wp6 — Inspect, apply and recover client integrations from the terminal

Fifteen assigned task rows now have named workflows. Operators can inspect a proposed client change, optionally bind application to that observation, set or clear Droid defaults, retire confirmed recovery history, refresh Aside profiles, save a runtime Desktop profile, inspect Cursor installation hints, read Hub state and update maintenance policy. The capability index reaches 320 entries. Browser-session-only Remote Workspace mutations remain excluded.

## Contracts preserved

Preview is observation, including a refused or no-op plan. An optional commit token binds the exact action/profile/options at the existing server owner; stale state requires a new explicit preview. Direct legacy mutations remain available. Droid defaults distinguish omitted inheritance, full replacement and explicit clearing. Journal retirement reports incomplete snapshot cleanup after the record was retired, without claiming rollback or retrying deletion.

Aside synchronization uses its established local attestation helper unchanged. Desktop runtime import saves desired state without applying it or falling back to a local profile. Cursor operations inspect status or an installer link; they never install software. Hub observations are selected before executor storage. The outer management dispatcher can return HTTP200 with available:false, which the CLI reports as unavailable with exit1 rather than successful emptiness. Runtime availability remains a codex/claude/pi object.

Storage policy writes preserve omitted settings and do not run cleanup. Explicit forced link revoke requires confirmation and describes remote cleanup as skipped, or unverified for an already-missing link. It never claims the remote client disconnected. New fixed management requests reject redirects; no global legacy transport or server authorization change was introduced.

## Limits and next phase

The full local suite was not repeated across concurrent worktrees. Exact-head hosted CI supplies broad coverage for publication; pending, skipped or cancelled jobs are not passing evidence. CLI transport fixtures do not prove server persistence or coordinated binding; the separate real owner tests supply that proof. No live OAuth, paid provider request, installed application modification, service restart, pairing or remote command was performed.

Two assumptions were disproved: that a leaf accepting inline options meant public dispatch accepted them, and that enum string coercion preserved wire types. The original Hub source inventory also missed the outer disabled-state response and was corrected before verification. Any contrary target/identity/partial-outcome result reopens the relevant task. Next is wp7, revalidating observation fidelity and chosen-key API tools from its own P/A cycle.
