## wp4 executable refinement

These decisions supersede ambiguous wording above. The parent is 7209223a36 after the test-only hosted-CI follow-up recorded in 041. Same-architect and security consultations are source advice; final reflection and independent A must accept this concrete amendment before B.

**CP-ARCH-03 / identity and input.** Live custom add sends only provider/modelId and the existing optional display/context/modalities/reasoning fields to POST /api/custom-models. Context is a positive safe integer; explicit empty reasoning is [], omission/inherit remains absent. Extract existing parseReasoningArgs into the pure models-custom-input.ts and re-export from models.ts, preserving its contract and avoiding a parent/live import cycle. New live diagnostics never print its interpolated error strings. All new live commands parse duplicates/conflicts before target discovery and use fixed routes, one pinned runtime and redirect:error. Reuse readJsonInput/serializeManagementJson and their existing limit/deadline/cleanup contract.

Live remove checks --yes before mutation, GETs the complete custom entry array, validates all identities and duplicate stored IDs, then resolves either exact stored id or provider/raw selector through resolveSlugSelection once for that provider's complete roster. Do not prefer exact over multiple matched collision rows, resolve per-row, use display names/UUID prefixes, or decode dash/slash spellings by guesswork. Zero match is not-found; multiple matches or malformed roster is refusal with zero DELETE. Encode only the resolved stored id in the DELETE path. This is not revision-protected deletion; no alternate-ID retry or local fallback.

**CP-UX-03 / local outcomes.** Main extracts only the pure wp3 projection into local-sync-result.ts: `projectLocalSyncResult(result: CodexSyncResult): LocalSyncResult`, with the existing status/normalized ok/configApplied/catalog evidence and no I/O. Provider add --sync retains its already-tested required-action policy. Local model add/remove remain opportunistic: absent proxy produces saved state, needsSync:true and exit0; attempted failure/refusal/nonconverged applied result is nonzero, policy-skipped ok:true is0, and only complete applied sync clears needsSync. Quiet sync produces one JSON document, with safe fixed errors and no backend paths/messages. Local JSON remove requires --yes instead of prompting; text removal retains the existing interactive cancellation behavior. Main may inject liveness/sync dependencies for isolated tests without adding user-visible flags or target overrides.

**CP-ARCH-03 / shared output primitives.** Main owns catalog-command-result.ts with `runCatalogAction(action: () => Promise<number | void>, knownErrors?: Readonly<Record<string,string>>): Promise<number>` and `printCatalogResult(data: Record<string,unknown>, refresh: unknown, wantsJson: boolean, lines: readonly string[]): number`. The runner emits static usage/fixed known-code or status messages, never arbitrary nested error/issues/body text; HTTP404→4,409→5, other failure1, usage2. The printer accepts only caller-validated public domain fields, normalizes the separate refresh through normalizeCatalogDisposition, appends it and prints via terminal-safe printData. Required malformed/missing refresh refuses before output. Fully committed nondegraded refresh returns0; failed/skipped/degraded refresh preserves saved data and returns1. It never chooses routes, validates domain DTOs, performs retries or creates a generic CRUD layer. Existing provider receipt behavior stays unchanged.

Each domain owns its actual success/partial DTO validation: custom add is the stored entry plus catalogRefresh (201), delete is ok:true plus refresh; picker saves have ok/pickerOrder/pickerOrderMode/applied/force, where applied is the featured roster rather than client convergence; display names expose provider/modelId/label/override/source; policy writes expose success/id/model/profile/revision data; combo writes expose success/id/model/combo. Do not feed those bodies to provider-result or blindly stringify them. Display-name HTTP503 with saved:true and valid matching provider/modelId plus failed refresh is a recognized saved-but-unconverged response: project its safe fields, emit the receipt and return1 without retry or claiming rollback. Other malformed/error bodies remain fixed diagnostics. Verify request identity against returned identity when supplied.

**CP-UX-01 / picker operations.** Status returns validated saved order/mode, chosen roster when supplied and routed-only pickerAvailable without dropping bare native saved IDs. Default/reset sends exactly {pickerOrder:null,pickerOrderMode:null}, never models/force. Both manual and non-default presets refuse a native-inclusive saved order until explicit reset/default. This deliberate CLI constraint prevents lossy replacement; it does not claim the GUI selector itself enforces the same extra step. Non-default mode with no routed candidates refuses rather than silently clearing order.

Manual --models CSV is a complete permutation of the current routed candidates. Reject blank, duplicate, missing, unknown or ambiguous tokens before PUT; canonical public IDs take precedence over observed legacy provider/raw spellings, and no token is silently dropped/deduped. Require known chosen state and collision-free complete identity coverage. The exact fixed featured prefix follows the GUI customPickerRows rules, including last chosen occurrence and canonical-rank preference. Immediately before manual PUT, re-read settings and /api/models identities on the same pinned target; refuse any change to candidates/chosen/saved order/mode/identity signature. This is an observational race check, not CAS. Presets do not prepend the manual fixed prefix: they use the GUI's en-locale sort over routed pickerAvailable. Most-used reads /api/usage?range=all&surface=all, refuses incomplete/invalid observations, maps requested model buckets through exact observed provider/raw identities and retains unranked candidates; resolvedModel is not aggregate attribution.

Pure model-picker-ordering.ts implements only the needed GUI projection/identity rules without importing GUI production code. Independent known-result fixtures plus test-only conformance against gui/src/model-picker-order.ts cover all modes, fixed-prefix/manual normalization and raw/encoded/native collisions. Test-only conformance is run explicitly, not assumed discoverable by imports.

**CP-UX-03 / model display names.** display-name P/M uses provider plus the raw upstream model ID, splitting the first slash and preserving the rest. It does not guess a public alias/encoded slug into raw modelId. --set and --clear are exclusive and one is required; clear sends null, blank set refuses. Reuse existing model/provider/display-name validators, percent-encode the provider path segment only and preserve the body model ID. Declare the existing regex management route; do not change its handler.

**CP-ARCH-03 / profile files and revision.** --file is editable-only, with keys alias/candidates/require/optimize/limits/unknownEvidence/compatibility as supported by the current writable contract. Reject id/model/revision and unknown nested keys/basic wrong shapes rather than silently stripping them. Documentation derives an editable document from show with an explicit projection; --expected-revision remains a separate required nonblank opaque string for update. Strict CLI field/shape validation precedes requests; the existing server routingProfileIssues runs contextual provider/alias/semantic validation. Never call it with dummy config, fetch a replacement revision, default update to create or retry409. Create is one mode:create PUT, update one mode:update PUT with the exact caller revision, removal one exact-ID DELETE with --yes and no invented revision protection. Creation/update may activate Lab and already-enabled automation; documentation names this effect and fixtures isolate it.

**CP-UX-01 / combo extensions.** Parse all new flags and bounded file input before the existing set flow's first HTTP read. `prepareComboInput(args, deps)` consumes only --targets-file, --image-input, --reasoning-effort-mode and --native-alias forms, leaving existing scalar flags for main. --targets-file and --targets are exclusive; targets-file is a nonempty ordered array of {provider,model,weight?,reasoningEfforts?,modelProfile?,lastResort?} with strict supported keys/types. Target efforts are nonempty unique low/medium/high/xhigh/max/ultra, separate from custom-model none/minimal/empty semantics. Do not invent config/provider context to run contextual validators; the server retains graph/profile/alias authority.

Bare legacy --native-alias means true; explicit on/off means true/false and duplicates or invalid values refuse. Presence-based assignment preserves false. Explicit image-input auto overrides the existing disabled carry; explicit reasoning-effort-mode strict overrides adaptive and never aliases defaultEffortMode. Omission preserves existing values and complete target metadata on partial edits. Replacement target files retain order and explicit lastResort:false, leaving the server's omitted lastResort carry intact. Off with an incompatible retained native alias may correctly fail; successful removal pairs off with an alias clear. Pin the read/merge/write target and serialize the exact final body; this upsert/rename is not CAS and never becomes delete/create.

**CP-UX-03 / JEV report.** Stats takes the exact stored combo ID and supported range (default30d), sends only jev=1/comboId/range to usage, and emits validated actual decision/outcome/attempt/token/coverage/nullable-average and incompleteness fields. No monetary cost or comparative savings metric exists in this DTO. Preserve zero observations versus missing/null measurements and incomplete history; do not replace missing values with measured zeros. No decision probe, model call or polling loop is introduced.
