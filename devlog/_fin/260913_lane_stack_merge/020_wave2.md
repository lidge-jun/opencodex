## Staleness handling

Each lane thread performs one final `git merge origin/dev` on its tip and
re-pushes before reporting, so the tip CI run the main session gates on was
produced against a head that already contains every earlier landed lane.

If a lane tip's run predates a newer dev landing, the main session requests one
more tip re-merge instead of merging on stale evidence.
