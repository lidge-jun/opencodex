Phase timeline

010 · M

클라이언트 연결 상태와 Claude 기본 실행 preview

depends on: none

Desktop/GUI의 한 화면에서 Codex와 Claude Code가 지금 어디로 가는지(OpenCodex proxy, native 로그인, Remote Link Home), 누가 설정을 소유하는지, 원하는 상태와 실제 파일이 왜 다른지, 되돌리면 어떤 키가 어떻게 바뀌는지를 본다. Claude Code의 기존 first-party 토글은 켜기 전에 settings.json에서 바뀔 키를 미리 보여 주고, 사용자가 명시적으로 등록한 Claude home마다 상태를 보여 준다.

020 · L

이주·온보딩: 발견, 일괄 가져오기, 링크, 속도 측정, 팀 접속

depends on: 010

다른 도구에서 넘어오는 사용자가 키를 다시 입력하지 않고 기존 공급자 설정을 발견·검토·가져오고, Codex/Claude 계정 파일을 일괄 가져온다. 공유받은 링크로 공급자 preset이나 Hub 접속을 미리 보고 확인한 뒤에만 기존 흐름을 시작한다. 공급자 후보 URL의 응답 시간을 같은 조건에서 비교한다.

030 · L

클라이언트 범위와 설정 이식성: Gemini CLI, Zed, MCP 동기화, 로컬 백업

depends on: 010

Gemini CLI와 Zed를 opt-in으로 OpenCodex에 연결하고 원복한다. 여러 파일을 쓰는 연결이 중간에 프로세스가 죽어도 다음 시작 때 일관된 상태로 돌아온다. Codex/Claude Code의 MCP 서버 항목을 읽고 고른 항목만 적용한다. 관리 설정을 골라 로컬 백업 번들로 내보내고 복원 전 변경을 본다.

040 · XL (구현 단위 둘: 040a = G-012, G-013, G-016 · 040b = G-014 → G-015, G-017)

계정 풀 스케줄링과 egress

depends on: none

같은 provider pool 안에서 계정마다 다른 upstream proxy를 쓴다. 확인된 quota cooldown이 재시작 뒤에도 유지된다. Codex·Claude OAuth 계정에 동시 실행 상한과 짧은 대기열이 생기고, 기존 priority tier 안에서 정적 weight와 실시간 부하로 계정을 고른다. 계정별 eligibility·refresh·cooldown 진단과 최근 fallback 결정의 후보·제외 사유를 본다.

050 · XL (G-021은 별도 구현 단위)

세션 연속성과 캐시

depends on: 040

긴 코딩 대화에서 combo가 이미 캐시가 따뜻한 대상을 유지해 cache miss를 줄인다. Antigravity와 xAI 경로에서 클라이언트가 돌려주지 않은 reasoning·서명 문맥을 안전하게 복원한다. 실제 Claude CLI를 쓰는 경로에 계정별 세션 재사용 opt-in 모드를 둔다.

060 · L

wire 충실도: 첨부 전용 turn, Gemini Interactions egress, xAI upstream WS

depends on: 040

Codex와 Claude Code의 첨부 전용 turn, file-backed 첨부, PDF, 여러 modality의 tool result가 대상 공급자 능력에 맞게 보존되거나 전송 전에 명확히 거절된다. Gemini Interactions를 공급자 네이티브로 보내는 opt-in 모드와 xAI upstream WebSocket 전송을 제공한다.

070 · L

공유 프록시 거버넌스: 발급 키 단위 동시 상한, 키 예산, 키 만료, 관리 감사

depends on: 040

proxy 하나를 여러 사람이 쓰는 팀이 발급 키마다 동시 실행 상한, request/token 예산, 만료 시각을 정하고, 키와 설정 변경을 감사 기록으로 본다. 정책이 없는 설치의 동작은 바뀌지 않는다.

080 · L

관측성: Claude Code statusline, 운영 알림, 네이티브 세션 사용량, 읽기 전용 관리 MCP

depends on: 070

Claude Code 사용자가 statusline에서 현재 세션의 실제 대상과 quota를 본다. 운영자는 실패·지연·429 임계치 알림을 켤 수 있고, proxy를 거치지 않은 네이티브 Codex/Claude 세션 사용량도 출처 표시와 함께 본다. 관리 권한이 있는 에이전트는 읽기 전용 MCP로 health·usage·키 metadata를 조회한다.

090 · L

요청 정책: outbound payload rule·요청 filter seam, 요청 masking

depends on: 060, 070

운영자가 특정 공급자/모델 요청에 반복되는 소수의 default·drop 규칙을 지정하고, 명시적으로 등록한 요청 filter를 실제 outbound body가 만들어진 지점에서 실행한다. 기본 off인 요청 masking으로 지정 패턴을 업스트림 전송 전에 가리고, 실패하면 물리적 전송이 한 번도 일어나지 않는다.
