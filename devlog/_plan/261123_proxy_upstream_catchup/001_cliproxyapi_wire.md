# 001 — CLIProxyAPI wire · L1

비교 기준은 CLIProxyAPI `0d251842d2539194ebd55ef0cdcf9c08f9c4908a`와 OpenCodex `origin/dev@9e0e298ef9`의 지정 export다. `cpa:`, `ocx:`, `mgp:` 인용은 각 고정 소스 루트에 상대적이다. 상태는 행에 적은 동작 단위에 적용한다. HTTP/WS 방향, 모델, 설정에 따라 같은 표면의 상태가 달라진다.

## 요약

1. Codex와 Claude Code의 주 경로는 양쪽에 있다. 다운스트림 Responses WS ↔ 내부 스트림, Claude Messages의 native/routed SSE, compact와 모델 목록은 기반 기능으로 다시 개발할 필요가 없다.
2. Antigravity의 기존 replay 우선순위는 범위를 좁힌다. OpenCodex에 세션별 다중 서명, 재시작을 위한 snapshot, 오류 시 제거가 있다. 비교할 차이는 CPA의 이전 문맥과 part 위치 대조, native call 복원, snapshot 조건부 갱신이다.
3. xAI의 과거 forward-only 판정은 닫혔다. OpenCodex는 Grok 모델별 Responses 선택과 replay 정규화를 제공한다. CPA의 세션별 completion 보강과 xAI upstream WS는 별도 차이다.
4. 첨부 단독 턴의 손실을 전송 전에 드러내는 동작은 두 클라이언트에서 직접 체감된다. 공급자별 표현 가능성에 맞춰 기존 호환 가드를 점검할 가치가 있다.
5. Gemini API 클라이언트는 이미 OpenCodex에 연결된다. CPA와의 차이는 Gemini Interactions의 공급자 네이티브 전송이다.
6. 소규모 공유 프록시에서 replay를 확장하려면 호출자·대상·세션 소유권, 바이트 예산과 종료 상태를 함께 유지해야 한다. 양쪽의 모델 목록은 실제 대상의 모델 및 wire 능력을 투영한다.
7. Kiro 전용 wire는 OpenCodex에 있다. Claude CCH, 독립 TTS, legacy Completions의 표면 차이는 아래 후보에서 제품 채택 가치와 함께 기록했다.

### 주요 wire 경로의 실행 순서

- **Codex Responses·WS.** CPA WS는 이전 턴의 pending tool output과 새 transcript를 먼저 분류한다. native continuation이 가능하면 `previous_response_id`와 delta를 보존하고, 그 외에는 이전 입력·출력·이번 입력을 합치거나 compaction transcript를 교체한다. OpenCodex는 다운스트림 `response.create`를 공통 Responses handler로 보내고, local replay miss이면 upstream이 omitted history를 소유하는 경우에 한해 parent ID를 넘긴다. canonical Codex나 translated route에서 그 조건이 깨지면 `previous_response_not_found`를 보내 full-context 재전송을 요구한다. `cpa:sdk/api/handlers/openai/openai_responses_websocket_requests.go:101`, `cpa:sdk/api/handlers/openai/openai_responses_websocket_requests.go:121`, `cpa:sdk/api/handlers/openai/openai_responses_websocket_requests.go:154`, `ocx:src/server/index/websocket-handler.ts:385`, `ocx:src/server/responses/request-prepare.ts:1505`, `ocx:src/server/responses/request-prepare.ts:1531`.
- **Claude Messages·SSE.** CPA의 routed Claude executor는 request envelope 변환, thinking·tool choice, cache control, 최종 wire 확정의 순서로 처리한다. Claude ingress의 선택 대상이 Codex면 Messages의 image/document/tool_result와 effort를 Codex 항목으로 옮기고 Responses event를 `message_delta/message_stop`으로 돌려준다. OpenCodex도 routed request를 공통 Responses로 보내지만 native Messages 선택은 별도 gate다. managed native와 OAuth 확장은 선택된 pool 정책을 고려하며, direct encoder는 명시적 opt-in이다. `cpa:internal/runtime/executor/claude_executor_execute.go:88`, `cpa:internal/runtime/executor/claude_executor_execute.go:158`, `cpa:internal/translator/codex/claude/codex_claude_request.go:436`, `cpa:internal/translator/codex/claude/codex_claude_request.go:594`, `cpa:internal/translator/codex/claude/codex_claude_response.go:206`, `ocx:src/protocols/settings.ts:95`, `ocx:src/server/claude-messages.ts:1224`, `ocx:src/server/claude-messages.ts:1316`.
- **Antigravity replay.** CPA는 signature 오류 및 pairing 거절에서 읽었던 snapshot을 기준으로 삭제하고, terminal 전이나 streaming call이 끝나지 않은 경우 새 ledger를 저장하지 않는다. OpenCodex Google adapter는 SSE의 part 단위로 관찰하여 다음 turn에 서명을 공급하며 session rejection과 durable call signature eviction은 별도 판정한다. CAP-antigravity-replay의 차이는 이 수명과 매칭에서 나온다. `cpa:internal/runtime/executor/antigravity_reasoning_replay.go:874`, `cpa:internal/runtime/executor/antigravity_reasoning_replay.go:898`, `cpa:internal/runtime/executor/antigravity_reasoning_replay.go:3647`, `ocx:src/adapters/google.ts:956`, `ocx:src/adapters/google.ts:1506`.
- **xAI HTTP·WS.** CPA HTTP 요청은 xAI Responses wire를 준비하고, WS는 같은 준비에 response ID 변환과 소켓 session을 더한다. replay는 이미 WS parent ID가 있는 continuation에서 건너뛴다. Assistant 문맥이 불일치하면 replay 삽입을 생략하며, 복구할 call에는 대응 output이 있어야 한다. Replay 가능한 결과가 없는 완료는 이전 항목을 지우고, 저장 backend 오류에서는 이전 상태를 유지한다. `cpa:internal/runtime/executor/xai_executor_execute.go:39`, `cpa:internal/runtime/executor/xai_websockets_executor.go:699`, `cpa:internal/runtime/executor/xai_websockets_executor.go:720`, `cpa:internal/runtime/executor/xai_reasoning_replay.go:67`, `cpa:internal/runtime/executor/xai_reasoning_replay.go:149`, `cpa:internal/runtime/executor/xai_reasoning_replay.go:313`.
- **Gemini Interactions.** CPA의 Interactions 전용 executor는 native 지원 source format과 선택 provider 조건으로 나뉜다. OpenCodex의 Gemini route는 method 검증, 사용 설정과 admission을 거쳐 Interactions create를 local state와 함께 Chat으로 실행한다. Gemini native generate gate는 `method`만 대상으로 삼는다. `cpa:internal/runtime/executor/gemini_executor.go:75`, `cpa:internal/runtime/executor/gemini_executor.go:1177`, `ocx:src/server/index/gemini-routes.ts:59`, `ocx:src/server/index/gemini-routes.ts:120`, `ocx:src/server/gemini-interactions-inbound.ts:84`.
