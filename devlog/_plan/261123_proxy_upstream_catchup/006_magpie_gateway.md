# 006 — Magpie gateway와 runtime

기준은 Magpie `3377e77eb697609727c675efe1fbcc9c5b33e54a`와 OpenCodex `origin/dev` `9e0e298ef9720cfeaa1209f090a68e4d1965d2a1`이다. `mgp:`와 `ocx:`는 각각 `.tmp/chase/magpie/`와 `.tmp/chase/opencodex-dev/`를 뜻한다. 비교 상태는 소스에서 따라간 범위에 적용한다.

## 요약

- 개인 사용자에게 가장 직접적인 차이는 장시간 대화의 캐시 비용이다. Magpie는 대화별로 특정 그룹 대상과 계정을 유지하고 cache read/write 및 TTL을 사용한다. OpenCodex도 Codex 계정과 provider 키에 캐시 affinity가 있고 JEV에 선택형 세션 pin이 있다. 일반 combo가 따뜻한 대상을 유지하는 범위를 우선 비교할 가치가 있다.
- Codex Responses, Claude Messages, Chat Completions, Gemini 생성은 양쪽에 있다. Magpie의 Responses WS는 `response.create`와 `response.interrupt`를 처리한다. OpenCodex는 활성화된 네이티브 전송에서 `response.steer`와 `response.inject`까지 처리한다.
- Magpie는 전송 오류로 만든 502도 아직 보류 중이면 후보를 바꿀 수 있다. OpenCodex는 처리 여부가 불명확한 재전송을 기본 거절하며 자족적 body에 대한 운영자 허용과 시도 예산을 따로 둔다. 두 동작 차이만으로 503 발생 빈도나 중복 과금 빈도를 판단할 수 없다.
- OpenCodex도 실제 Claude Code CLI를 실행한다. 남은 차이는 Magpie의 계정별 장기 프로세스와 resume, 대기 중인 도구 결과의 연결이다. OpenCodex의 `claude-cli`는 매 턴 stateless이고 클라이언트가 도구 실행을 소유한다.
- 소규모 팀은 gateway key 범위에 맞춘 Claude Code statusline과 quota/cache 표시를 통해 세션의 실제 대상을 바로 볼 수 있다. OpenCodex에는 이에 사용할 quota, usage, key admission이 이미 있다.
- Magpie의 확장점은 `moejs` 인프로세스 body/event 미들웨어, Bun subprocess의 provider/auth 호스트, 설정된 요청 masking으로 나뉜다. OpenCodex의 로컬 플러그인 계약은 outbound URL/headers에 집중한다.
- 10월 17일 Aside 조사에서 언급된 6개 라우팅과 direct-HTTP 전용 Claude 비교는 이 기준점에서 갱신했다. 현재 Magpie 소스에는 기본 Smart와 11개 등록형 전략이 있고 OpenCodex에 CLI adapter가 있다. 이전 기록은 Aside의 projects/opencodex.md 「Magpie competitive teardown」을 참조했다.

### 등록된 번역 쌍

네 입구는 공통 `Request`와 `Event`를 통해 서로 변환된다. 아래 `native/IR`은 대상이 해당 wire를 지원하면 relay하고, 변환이나 수집이 필요하면 IR로 갈 수 있다는 뜻이다. 실제 후보는 provider가 가진 `Speaks` 및 모델별 API, relay 가능 여부, compaction/봉인 상태, 모달리티에 의해 제한된다. translated non-stream도 upstream에는 stream으로 요청한 뒤 모아 client JSON으로 렌더링한다. `mgp:internal/provider/provider.go:2259`, `mgp:internal/gateway/gateway.go:6253`, `mgp:internal/gateway/gateway.go:6380`, `mgp:internal/gateway/gateway.go:9962`, `mgp:internal/gateway/gateway.go:10034`, `mgp:internal/gateway/gateway.go:10194`.

| 입력 → 출력 wire | Chat | Responses | Anthropic | Gemini |
| --- | --- | --- | --- | --- |
| Chat | native/IR | IR | IR | IR |
| Responses | IR | native/IR | IR | IR |
| Anthropic | IR | IR | native/IR | IR |
| Gemini | IR | IR | IR | native/IR |

공통 등록은 `parseRequest`, `buildFor/build`, `decoder/makeEncoder`다. Vertex 빌더와 Code Assist 응답 decoder가 Gemini 계열의 추가 upstream 변형을 다룬다. 같은 프로토콜의 모든 기능이 보존된다는 판정에는 이 맵을 사용하지 않았다. `mgp:internal/gateway/gateway.go:10347`, `mgp:internal/gateway/gateway.go:10404`, `mgp:internal/gateway/gateway.go:10432`, `mgp:internal/gateway/gateway.go:10492`, `mgp:internal/gateway/gateway.go:10648`.
