## Activation and observable proof

1. Two fake Antigravity accounts. A first 401 triggers same-account refresh and succeeds on the same account: **zero pool rotation**. If the same-account replay returns 401 again, the eligible sibling receives one budgeted send and can succeed. If terminal refresh fails, a live unpaused sibling still gets one budgeted attempt even though the failed row now needs reauth; no sibling/budget returns the sanitized 401. A one-account pool never rotates.
2. A 403 body whose only validation evidence is `error.details[0].reason = "VALIDATION_REQUIRED"` is normalized to a stable, sanitized marker and rotates through the adapter path. The raw passthrough path classifies the same structured reason. A plain `PERMISSION_DENIED`, unrelated provider's 401, marker beyond 4096 bytes, incomplete/timed-out body, or abort sends no retry and returns the original/safe error.
3. Pause the sole alternate between initial selection and commit: no retry uses it. Replace the failed credential during a refresh: stale failure evidence does not cool the new generation. Account/project/token stay paired through the successful alternate.
4. Drive adapter dispatch, native passthrough, continuation and normalized runTurn error fixtures separately. Each records the provider response, number of physical sends, selected account, budget result and client-visible terminal answer. A sidecar 401/403 fixture remains terminal by stated scope; ordinary 429, Kiro and Anthropic behavior is unchanged.
5. A native main account at 98% in either 5-hour or weekly evidence still hard-locks. Reset credit alone cannot release it; fresh lower usage can. The new generic status path cannot activate for `openai` or `anthropic`. The output-commit guard prevents a cross-account resend after text or tool effects.

Run the named Google formatter, OAuth failover and Antigravity server tests, plus the relevant Kiro refusal, hard-lock policy/default/recovery, reset-credit recovery and paused-preservation tests. After a committed checkpoint, run `bun run test:changed` from a same-commit `/private/tmp/t4-account-pool-verify` checkout, then `bun run typecheck`, `bun run privacy:scan`, and `bun run structure:check`. The existing tests import the changed modules, but `test:changed` cannot discover source-oracle and data-file dependencies, so the named files are explicit. Require independent auth security review and resolve correct review findings before merge.

## Field and bypass chain

No new persisted field or enum is added. The transient classification is created from a response status and bounded body, consumed by the four primary inference paths, and never serialized/deserialized (N/A: no disk or management DTO). Executing surface is the proxy runtime; Codexclaw E1–E8 process tiers do not gate an installed proxy. Direct provider calls, image/web-search sidecars and requests that have already committed output bypass this recovery opportunity. A validation marker beyond the bound intentionally stays a terminal 403. Wording is limited to bounded pre-output primary-inference rotation; final enforcement layer for traffic outside this proxy: none.
