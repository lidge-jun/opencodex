## Reflection (same architect, 01a11f35): MISALIGNED → dispositions

These replace the matching rows above.

- **R1 (amended).** Leftover journal cleanup runs only under the lock, only after the current record was read and validated successfully, and only for regular files in `journal/` that match the journal name pattern and are not referenced by the record's `pending`. A corrupt or unreadable record never triggers cleanup. Why it is safe: a referenced journal is kept; an unreferenced file is either from an unsaved transaction (never applied) or from a transaction whose final record is already saved (its changes are recorded in the settled record), so neither is needed for recovery. The name validator accepts both `<generation>-<index>.json` (records written by bcbd0363be) and `<generation>-<txid>-<index>.json`. Tests: crash before the pending save; crash after the final save and before journal deletion; corrupt record leaves the journal dir untouched; referenced journal kept.
- **R2 (amended).** The broadcast debt lives outside `windows`: a top-level record field `notifyPending: bool` with `#[serde(default)]` (old records read as false), set in the same record save that starts any registry change (install, repair, remove, rollback) and cleared only after a successful broadcast. It survives Remove (which clears `windows`). It is not `pending`; the 020 reader ignores it and handoff is never blocked by it. Fixtures: one record with `notifyPending: true` (reader → `ready`), and the existing fixtures without the field.
- **R3 (amended).** Every disabled path (Remove, Off, disabled reconcile at launch) reads the record first and uses only the recorded ownership list; `targets()` runs only for an enabled reconcile or Repair. Tests cover each of the three paths with an unrepresentable `ZDOTDIR`.
- **R4 (amended).** The generation check applies to errors as well as results; when a poll is in flight at the end of an action, the action schedules one more status read after that poll settles. Test covers both.
- **R5 (amended).** The main-label and exact-URL guard stay. Tests: ready dashboard → dashboard URL; no ready dashboard → bundled startup page.
- **S1 (amended).** Every Store open checks each existing private path (root, `bin`, `journal`, `backups`, `cli.json`, `lock`, shim, `path.sh`, each journal and backup file): owned by the current user, mode as expected, no extended ACL (macOS `acl_get_file` returns none or an empty ACL; Linux no `system.posix_acl_access`/`system.posix_acl_default` xattr). Newly created paths are cleared and then verified. Any existing path that fails is refused (`private-acl-unsafe`) and nothing is written; status tells the user which path. FFI: macOS `acl_get_file`/`acl_set_file`/`acl_init`/`acl_free`/`acl_get_entry` from libSystem with the documented constants, every allocation freed, any non-zero return treated as failure; Linux `getxattr`/`removexattr` from libc. Windows: `icacls` resolved as `%SystemRoot%\System32\icacls.exe` (absolute, `SystemRoot` read from the environment and validated as an absolute drive path), the current user SID from the process token (`OpenProcessToken` + `GetTokenInformation(TokenUser)` + `ConvertSidToStringSidW`), `Command` without a shell, a 10-second timeout after which the child is killed and waited, then `icacls <root>` output parsed to verify the DACL is protected (no inherited ACEs) and contains only the user SID, SYSTEM and Administrators; anything else refuses.

## A audit round 1 (01a11f6b): FAIL → dispositions

- **S1-macOS (blocker 1).** ACL inspection distinguishes three outcomes, each with its own return convention: `acl_get_file` returning NULL with `errno == ENOENT` means no ACL (accepted); a non-NULL ACL is walked with `acl_get_entry(acl, ACL_FIRST_ENTRY, &e)` then `ACL_NEXT_ENTRY`, where a return of `0` means an entry exists (refuse), and `-1` with `errno == EINVAL` on the first call means an empty ACL (accepted); any other NULL/`-1` is an inspection failure (refuse with `private-acl-unsafe`). Every ACL handle is freed with `acl_free`. Tests: empty ACL accepted; single inherited entry refused (created with `chmod +a` on a temp parent, and after clearing, accepted); inspection on a missing path is a failure; a fresh Store opens normally (positive case).
- **S1-Windows (blocker 2).** `icacls` is used only to set the policy (grant user SID with `(OI)(CI)F`, `/inheritance:r`, remove broad SIDs). Verification reads the native security descriptor with `GetNamedSecurityInfoW(OWNER | DACL)` and `GetSecurityDescriptorControl`: owner SID equals the token user SID; `SE_DACL_PROTECTED` is set; every ACE is an allow ACE for the user SID, `S-1-5-18` (SYSTEM) or `S-1-5-32-544` (Administrators), compared as SIDs with `EqualSid`, never by name. A newly created child is verified the same way except that inherited ACEs from the hardened root are allowed. Tests on `mini`: hardened root accepted; a root with inheritance not removed (unprotected, no inherited ACEs) refused; a root with an extra explicit ACE for `S-1-1-0` refused. FFI: `advapi32` declarations only, `LocalFree` for every returned buffer.
- **R1.** A missing record (first install) counts as a validated empty record: unreferenced journal files are cleaned under the lock in that case too. Test: crash before the first pending save on a fresh root → the next install succeeds.
- **R2.** Tests cover a settled record that keeps `notifyPending: true` after a failed broadcast, a crash after the registry write and before the broadcast, Remove and rollback, each retried on the next run.
- **R3.** Tests go through the real selection entry point (`perform`/`reconcile` with the environment-reading target selector) for Remove, Off and disabled reconcile, with `ZDOTDIR` set to a value containing `:`.
- **S2.** When an rc ACL refusal leaves a block in place during Remove, the shim and `path.sh` are kept as well (the block still sources `path.sh`), and status reports `rc-acl-present`. Test asserts the three survive together.
- **C.** The `desktop shell` CI job installs `acl` (provides `setfacl`) next to its Tauri packages; a skipped Linux ACL test is not counted as evidence. `structure/desktop-shell.md` changes replace existing lines to stay within 600.


## A audit round 2 (01a11f6b): FAIL → dispositions

- **S1-Windows NULL DACL (blocker).** `GetNamedSecurityInfoW` must return a present, non-NULL DACL; a NULL DACL or a missing DACL refuses (`private-acl-unsafe`). The DACL must contain an allow ACE for the user SID granting `FILE_ALL_ACCESS` (or `GENERIC_ALL` mapped). Negative test on `mini`: owner and protection correct but DACL set to NULL with `SetNamedSecurityInfoW` → refused.
- **Root vs child rules.** Root: owner = user SID, `SE_DACL_PROTECTED`, only allowed SIDs, non-NULL DACL with the user's full-control ACE. Child: owner = user SID, non-NULL DACL, every ACE (inherited or explicit) for an allowed SID; protection not required. Tests: create root and a child, verify immediately, close, then open the Store again and verify both succeed.
- **Memory.** Only the security descriptor returned by `GetNamedSecurityInfoW` is released, with one `LocalFree`; owner and DACL pointers point inside it and are never freed separately. `ConvertSidToStringSidW` output (used only for logs, never compared) is freed with `LocalFree`.
- **macOS.** `NULL`/`ENOENT` from `acl_get_file` counts as "no ACL" only after an `lstat` of the same path succeeded; the missing-path test asserts failure.
