# C — CPA vs opencodex: outbound Gemini API (AI Studio key) and Vertex

Heads: opencodex `dev` = `d842c1352e` (worktree HEAD == origin/dev), PR #8742 = `pr/8742` `d21ed22ea8`, CPA = `devlog/_chase/_cca` `e96d4c4` (2026-11-15).
Method: source reading with `rg`/`sed` only. No tests, servers, or upstream calls were run.
NOT RUN: any runtime/wire capture against Google, `bun run test`, CPA `go test`.
CPA paths are relative to `devlog/_chase/_cca`; opencodex paths are relative to the repo root. "(inferred)" marks a conclusion drawn from code shape rather than read directly.

Scope note: CPA's `aistudio_executor.go` is a **websocket relay to the AI Studio web app** (`wsrelay`, aistudio_executor.go:1-49,96-102), not the public key-based API. The key-based Gemini API path is `gemini_executor.go`. Rows below compare opencodex's `google` adapter (googleMode `ai-studio` / `vertex`) with `gemini_executor.go` and `gemini_vertex_executor.go`. PR #8742 adds only a Gemini **inbound** surface that "never talks to Google itself" (structure/data-planes/gemini-inbound.md:3-6 on pr/8742), so its column is "no outbound change" unless noted.
