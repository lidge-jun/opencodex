# Implementation and validation map

This is one integrated work phase: release publication cannot safely use the new selector before every checkout, version gate, receipt and recovery path uses the selected source SHA. The following order describes dependencies inside that change, not independently shippable partial releases.

Owner scope clarification on 2026-11-08 supersedes signing redesign language
below: preserve existing desktop signing and address only regressions introduced
by this release flow. Historical signing hardening is follow-up work.

1. **Evidence and versions.** Modify `.github/workflows/ci.yml` to expose a stable machine-readable full-lane identity and retain its aggregate job assertions; add a release-owned selector under `.github/scripts/` or `scripts/` that validates authenticated repository/run/attempt, approved workflow blob hash, full paginated job graph, lane identity, full SHA, ancestry and the explicit legacy baseline. Extend `scripts/version-line.ts` with pure next-base and preview ordinal decisions. Modify focused `tests/ci-workflows/release-*.test.ts` and fixtures for forged titles, unknown workflow revision, wrong event/repository/branch/lane/attempt/conclusion, incomplete pagination, equal/older/divergent SHAs, legacy baseline, stable/preview semver and chronology; demonstrate these tests fail before implementation.
2. **Service evidence.** Modify `.github/workflows/service-lifecycle.yml` to dispatch a validated candidate SHA using the workflow revision's policy, check it out in all jobs, bind the resulting successful full matrix to that SHA, and avoid cancelling unrelated dispatches. Test no changes, accumulated service changes, missing/failed/PR/narrow/wrong-SHA evidence, and historical-SHA dispatch after dev advances. Keep PR macOS/Windows disabled and add no dev push.
3. **Release integration.** Modify `.github/workflows/release.yml`, `.github/scripts/release-dispatch-guard.cjs`, `scripts/ci/release-preflight.sh`, `scripts/release.ts` and affected verification/resume/release-notes helpers. Resolve source and version once under current dev workflow policy; pass outputs to every checkout and replace source-dependent `GITHUB_SHA` uses with the resolved SHA, including assets, npm `gitHead`, release notes, tags and resume. Stamp/check all four sources in every job before any build. Build npm tarballs in a no-OIDC/no-write job; a separate publisher verifies immutable artifact digest and runs no candidate-controlled scripts. Isolate Apple/SignPath signing from candidate builds where possible; explicitly document and independently review any build-time signing exception. Enforce a fail-closed `OCX_DEV_RELEASE_PUBLISH_ENABLED=true` hold for non-dry-run publication; test missing, false and true. Keep permissions scoped per job; do not run hosted release workflows from PR branches. Verify every existing safety gate, immutable action pin, asset validation and exact-SHA resume still applies. Test installer, updater and widget versions, preview-to-stable behavior, each refusal and absence of publication on failure.
4. **Policy, documentation, migration.** Update `MAINTAINERS.md`, `AGENTS.md`, `structure/ops/docs-and-release.md`, `structure/ops/cross-platform-ci.md`, and affected docs-site release/contributor translations. Update `.github/workflows/deploy-docs.yml`, `.github/workflows/catalog-async-contracts.yml`, branch enforcement and relevant CI tests; retain historic branches and the old bump workflow only as an explicitly disabled/manual migration tool or remove it only with separately authorized deletion. Explain exact coordinator settings, Pages stable-source deployment, OIDC identity, one-time lineage baseline, and 2.99.0 handoff.
5. **Review and proof.** Independently review technical correctness and security using separate `task.create` review lanes; record accepted/rebutted findings and rerun targeted checks after fixes. Run focused tests, `bun run typecheck`, `bun run structure:check`, `bun run privacy:scan`, and `bun run test` unless resource exception applies. Check complete workflow diffs and artifact/platform constraints. Open PR against dev with template and exact verification; link it through GOAT. Inspect current-head required CI. Request no production release or settings changes. Once approved for merge and merged, obtain green `lane=all` evidence and run `release.yml` with `dry-run=true` from trusted dev, reporting the actual run, SHA and result. Do not dispatch a release dry run from a PR-controlled workflow.

Apply the seven independent-audit amendments in `000_plan.md`: fixed full-dispatch graph and full-attempt evidence, explicit resume tuple, historical tag capability and provenance experiments as cutover blockers, zero release secrets on untrusted dry runs, cross-channel legacy mappings, and trusted-revision verifiers. Tests must exercise every refusal and the operator recovery paths.

**Threat boundary:** dispatch inputs, candidate source, run metadata, artifacts, registry responses and legacy tags are external inputs; trusted workflow revision, maintainer-approved dev history and repository permissions are the authorities. Threats include publishing untested or older code, wrong-source artifacts, credential exposure and partial publication. Controls are validated immutable source bindings, full job evidence, shared serialization, final rechecks, scoped tokens, pinned actions, and fail-closed recovery. These controls rely on GitHub repository administrators, workflow permissions and npm identity; administrators can change policy, so workflow checks are not an independent barrier to a malicious administrator.
