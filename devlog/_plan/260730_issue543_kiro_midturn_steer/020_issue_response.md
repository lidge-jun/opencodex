# 020 — 이슈 #543 응답 초안

의존: 010 (변경 내용을 코멘트에 반영해야 하므로)

## 목표

`AGENTS.md` 리뷰 정책상 이슈/PR 응답은 영어로 쓴다. 코멘트는 세 가지를 해야 한다.

1. 우리가 증명한 것을 정확히 말한다 — 프록시는 스티어링을 온전히 전달한다.
2. 증명하지 못한 것을 정직하게 구분한다 — 상류 opus-5의 대우는 미확정.
3. 신고자가 실행할 수 있는 결정적 캡처 절차를 준다.

## 절대 하지 말 것

- **GitHub 쓰기 금지.** 코멘트 게시, 라벨/제목/상태 변경은 사용자 승인 없이 하지 않는다.
  초안만 만들고 게시는 사용자가 결정한다.
- 우리 변경(010)이 #543을 고쳤다고 주장하지 않는다. 페이로드 위생 개선이고,
  상류 문제라면 증상은 남는다.
- 신고자가 이미 한 대조 실험을 다시 요구하지 않는다. 그건 무례하고 이미 유효하다.

## 코멘트가 담을 내용

- **확인된 사실**: `buildKiroPayload`를 두 모델에 대해 직접 실행해 비교한 결과,
  동일한 mid-turn tail에서 `conversationState.currentMessage`가 스티어링 텍스트를
  그대로 담는다. 대화 내용과 전송 구조는 두 모델이 같고, 다른 것은 modelId(정의상
  달라야 함)와 opus-5의 native `output_config.effort`뿐이다. "바이트 단위 동일"이라고
  쓰지 않는다 — modelId는 반드시 다르므로 과장이다.
- **감사한 경로**: inbound 블록 순서 보존, user turn 병합, `currentMessage` 선정,
  completionMode 결정(도구 유무만 의존), tool-catalog nudge(모델 무관),
  context window(둘 다 1M), 모델 정규화, continuation 캐시.
- **개선 사항 (targeted mitigation)**: 프록시 캐리어 문구가 사람 지시 앞에 오던 배치를
  바꿔, 사람 텍스트가 있으면 캐리어를 아예 넣지 않는다. 모델 패리티를 고정하는 회귀
  테스트를 추가했다. 이것을 **수정 완료가 아니라 표적 완화**로 표현하고,
  **패치 빌드로 A/B 재현**을 첫 후속 요청으로 제시한다 (리뷰 반영). opus-5가 첫 문장에
  가중치를 크게 준다면 이 변경만으로 증상이 사라질 수 있고, 그렇다면 그것이 곧 증거다.
- **남은 결정적 artifact**: opus-5에서 스티어링 텍스트가 실제로 wire에 실리는지,
  그리고 상류가 그것을 어떻게 다루는지. 소유자가 요청한 `OCX_QUEUE_543` 마커 캡처가
  여전히 유효한 방법이다. 우리가 확인한 정적 증거는 "마커는 실릴 것"을 예측한다.
- **effort 반증 실험 제안**: opus-5에서 reasoning effort를 낮추거나 끄고 동일 시나리오를
  재현. 그때 스티어링이 통하면 `output_config.effort`가 용의자로 승격되고, 여전히
  무시되면 남는 건 모델/상류 behavior다. 이건 신고자 환경에서만 가능하다.

## 위험

- 낮음. 문서/초안 작업이며 외부 상태를 바꾸지 않는다.
- 다만 "상류 문제"라고 단정하지 않도록 조심한다. 우리가 가진 것은 페이로드 동일성
  증거이고, 상류 내부 동작에 대한 직접 증거는 없다.
