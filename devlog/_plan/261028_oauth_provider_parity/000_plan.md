# 000 — Multi-Provider OAuth Protocol, Client Profile & Pool Isolation Plan

## Reader Summary (`READER-DOC-02`)

OpenCodex currently leaks cross-account client identifiers (`device_id` on Claude native passthrough, `x-codex-installation-id` and `x-oai-attestation` on Codex pools, un-scoped `request.sessionId` and `thoughtSignature` replay caches on Google Antigravity, and shared HTTP/2 sessions on Cursor), emits mismatched or outdated client fingerprints (`@anthropic-ai/sdk/0.74.0` vs `claude-cli/2.1.280`, static per-token `X-Claude-Code-Session-Id`, form-urlencoded Codex token refresh), and leaves gaps in 401/403/429 multi-account pool failover across Google Antigravity, Cursor, Claude, and Codex. This four-phase unit (`wp1` through `wp4`) aligns every provider's wire headers, OAuth refresh contracts, per-conversation session IDs, per-account device/installation IDs, and 401/403/429 pool protection with official client profiles (`claude-code-deobf`, `codex-rs`, `gemini-cli`) and reference proxies (`CLIProxyAPI`, `cliproxy-rs`, `cc-switch`), delivering each phase as an independently verified PR to `dev`. Full comparative evidence lives in [001_provider_parity_matrix.md](./001_provider_parity_matrix.md).
